# 主循环与日志地图

> 维护层运营参考：主循环里现在有哪些工具、各工具日志在哪、怎么读、什么内容。
> 接线**顺序/契约/失败降级**单一源 = `hook-chain.md`。本文给「环里有啥」速查 + **日志地图**（hook-chain 不含）。
> 注：下方主循环表镜像 `../harness/hook_manifest.json`，纳入 `多数据源治理方案.md` M1 治理（落地后加 RECONCILE 标记自动渲染）。

## 1. 主循环现状（环里有哪些）

每次交互触发的 hook（事件→链，详见 hook-chain.md）：

| 事件 | matcher | 链（按序） | 性质 |
|------|---------|-----------|------|
| UserPromptSubmit | * | changelog_inject → sync_inject → route_check → retrieve_inject | 注入（fail-open，无 block） |
| PreToolUse | Bash | dangerous_command_blocker | **S1 硬阻断** |
| PreToolUse | Write\|Edit\|MultiEdit | memory_file_protector → memory_lint_gate → doc_gate → diff_backup | **前 3 可 block**，diff_backup 静默 |
| PreToolUse | Read | read_large_file_guard | S2 软校验 |
| PreToolUse | Agent | agent_prompt_gate | S1 ask |
| PostToolUse | * | audit_logger | 只记日志 |
| PostToolUse | Write\|Edit | diff_show | 只展示 |
| PostToolUse | Bash | learning_opportunity_nudge | 注入提示 |
| SubagentStart/Stop | * | subagent_logger / subagent_stop_logger | 只记日志 |
| Stop | * | post_task_hook --auto-fix | CHANGELOG 自动 append |
| statusLine | * | statusline | 每帧 <50ms |

主循环外（手动/定时跑，不在每轮 hook 链）：maintain.py 各子命令、check_*、health/runner、gate_check、各 analyze/report。

## 2. 日志地图

全在 `~/.claude/logs/`。JSONL = 每行一条记录（勿 pretty-print 原地，破坏逐行解析）。

| 日志 | 产出者 | 内容 | 怎么读 |
|------|--------|------|--------|
| `harness_tool_invocations.jsonl` | `_lib.py` 共享 logger（work_context_pack / session_report 等多脚本） | 脚本调用证据：ts/script/source/cwd/argv/pid | 逐行 JSON；执行证据审计 |
| `tool_audit.jsonl` | `audit_logger.py`（PostToolUse *） | 每次工具调用：ts/session/tool/input_summary/cwd | 逐行 JSON；全工具流水 |
| `subagent_audit.jsonl` | `subagent_logger` + `subagent_stop_logger` | subagent 启停：agent_type/agent_id/耗时/输出大小 | `route_audit.py [--days N]` 统计 |
| `retrieve_calls.jsonl` | `retrieve_inject.py`（UserPromptSubmit） | 每轮召回：task/query/hit_count/top1_path/elapsed_ms | `view_retrieve_log.py [-n N] [--miss]`（人读）/ `analyze_retrieve_log.py --days 7`（统计） |
| `retrieve_calls.pretty.log` | 同上（人读镜像） | 多行可读版 | 直接看；勿当 JSONL 解析 |
| `retrieve_inject_debug.log` | retrieve_inject 调试 | 召回内部调试 | 排查召回异常时看 |
| `memory_writes.jsonl` | `memory_file_protector.py`（PreToolUse Write\|Edit） | 记忆库写入：ts/session/tool/file | 逐行 JSON；记忆变更流水 |
| `memory_lint_gate.jsonl` | `memory_lint_gate.py` | 记忆 lint 结果：file/tool/ok/report_head | 逐行 JSON；看哪次写被拦 |
| `health_checks.jsonl` | `health/runner.py`（maintain doctor） | 健康信号：check_id/status/headline/evidence（**~9MB**） | `maintain.py doctor --json`；勿全文 Read，grep check_id |
| `maintain.jsonl` | `maintain.py` | 每次维护运行：type/mode/summary{PASS/WARNING/ERROR}/results（**~5MB**） | `maintain.py status --json`；grep 不全 Read |
| `issues.jsonl` | `reporting/issue_tracker.py` | issue 账：issue_id/event(detected/resolved)/source/severity/title/evidence_hash | issue ledger；control_panel issue_loop 视图 |
| `governance_pulse.jsonl` | `governance_pulse.py` | 治理脉搏：gate_fail/gate_overdue/orphans/stale_registry/dual_storage | 逐行 JSON；趋势看治理健康 |

### 读日志铁律
- **大文件**（health_checks ~9MB / maintain ~5MB / retrieve_calls ~5MB）：禁全文 Read，用专用 reader 或 grep 定位。
- JSONL 保持逐行：分析用 `analyze_*` / `route_audit` / `maintain status`，别原地格式化。
- 人读用 pretty 镜像（retrieve_calls.pretty.log）或 reader 的可读输出。

## 3. 日志 → 哪层健康

| 想看 | 日志 + reader |
|------|--------------|
| 召回准不准（反馈层） | retrieve_calls + `analyze_retrieve_log.py` |
| subagent 派得对不对（执行层路由） | subagent_audit + `route_audit.py` |
| 记忆写入合规（沉淀层） | memory_writes + memory_lint_gate |
| 整体治理（维护层） | governance_pulse + issues + `maintain doctor` |
