## 1. 整体架构(v2.1 收窄,2026-04-24)

```
QMainWindow
  └─ QSplitter(水平,左主区 / 右侧栏)
       ├─ QWidget(左主区,垂直布局)
       │    ├─ QTabWidget(3 页签,QScrollArea 包裹各页)
       │    │    ├─ 状态(默认,合并 v1/v2.0 总览+守护+修复)
       │    │    ├─ 变更(读 CHANGELOG.md 倒序)
       │    │    └─ 任务(展示 active+archived 任务卡片)
       │    └─ DebugOutputDock(底部,默认折叠)
       └─ DocSidebarWidget(右侧固定 200~240px,关键文档跳转)
            └─ 4-6 个 QPushButton,点击=用默认编辑器打开文件
```

**v2.0 → v2.1 删除的结构**:
- ❌ 8 页签 → 3 页签(删 AI/事件/历史/同步,合并 总览+守护+修复 → 状态)
- ❌ 右侧 `QStackedWidget(ConclusionPanel)` 整体删除——简化"任务卡片点击"行为为"打开目录",不再渲染长简介
- ❌ 复杂的 polling 三通道(events/audit/outcomes)→ 见 §3 简化后通道

**关键 widget 选择**(v2.1 简化后):

| 用途 | PySide6 widget |
|---|---|
| 3 页签容器 | `QTabWidget` |
| 内容滚动 | `QScrollArea`(内建) |
| 状态卡片(Git/Daemon/修复) | `QFrame` + QSS 边框/底色 |
| 一键修复按钮 | `QPushButton` + qtawesome icon + spinner 状态 |
| 变更条目展示 | `QListWidget`(每条一行) + `QTextBrowser` 详情 |
| 任务卡片网格 | `QScrollArea + QGridLayout`,卡片是 `QFrame` 子类 |
| 关键文档侧栏 | `QVBoxLayout + QPushButton` × N,固定宽度 |
| 调试输出折叠区 | `QDockWidget` 或自实现 collapsible:`QToolButton(checkable)` + `QPlainTextEdit`,折叠时只占一行 |
| 调用 CLI 取数据 | `subprocess.run(...)`,QThread/QThreadPool 异步 |
| 左右分隔 | `QSplitter`(主区 vs 侧栏) |
| 主线程定时刷新 | `QTimer.timeout.connect()` |

## 3. 数据通道(v2.1 简化,2026-04-24)

### 3.1 通道清单(从 5 通道砍到 3 通道)

| 通道 | 用途 | 读取频率 | 执行线程 | 备注 |
|---|---|---|---|---|
| `git status --porcelain` | 状态页 Git 卡片 | **10s + QThread 异步** | 工作线程 | Windows cold cache 200-800ms,必须异步;同一时刻最多 1 个 git 子进程在跑(QThreadPool maxThreadCount=1 或 _busy 标志,REVIEW R2.3) |
| `summarize_status` + `summarize_doctor` | 状态页 Daemon / 修复卡片 | **5s** | 主线程 | 纯 Python 调 model 层,毫秒级 |
| `harness_status.py --tasks --json` | 任务页卡片 | **按需 + 手动刷新** | 工作线程 | 切到任务页或点刷新时拉一次;不轮询 |
| `CHANGELOG.md` 文件读 | 变更页 | **按需 + 手动刷新** | 主线程 | 切到变更页或点刷新时读;文件 < 1 MB,主线程 OK |

**v2.1 删除的通道**(原 v2.0 通道,本期下线):
- ❌ `control_panel_events.jsonl`(事件页删)
- ❌ `task_outcomes.jsonl`(账本/结论面板删)
- ❌ `tool_audit.jsonl`(守护页内嵌读取删,守护数据已通过 summarize_status 获取)

→ **§3.2 JSONL 半行容错代码不再需要**(无任何 view 直接读裸 append 的 jsonl)。原 polling.py 的 `read_incremental` 函数保留在代码库但不挂任何调用点,留作以后可能恢复事件页时复用。如确定不再恢复,Phase 1c 收尾时整段删除。

### 3.2 ~~JSONL 鲁棒读取~~ → 已删除依赖

> v2.0 设计的 polling 半行容错是为事件/账本页服务的,v2.1 这两页删除,容错逻辑失去使用方。**保留代码不删**(`polling.py` 的 5/5 单元测试也保留),但 main_window 不再 wire 任何 PollingService 实例。后续若有复活事件页的需求,直接挂回即可。

### 3.3 轮询机制选择:QTimer,不上 QFileSystemWatcher

理由不变:2-10s 延迟对人类感知够用;加 QFileSystemWatcher 引入文件锁竞争 + 跨平台行为差异(Windows 监听文件改动有 buffer / WSL 通过 9P 协议会丢事件);本期通道更少,QTimer 更显合理。

## 7. 详细设计

### 7.1 widget 树搭建方式 + 代码组织

**搭建方式:纯 Python 代码 widget 树**(不用 Qt Designer .ui 文件)

理由:
- 决策 3 按页签拆模块,每页是 `QWidget` 子类,纯代码在 `__init__` 里搭 layout 最自然
- 7 页签形态相似(标题 + QScrollArea + model 渲染区),可提取 `_BasePage` 基类复用,Designer 不好继承
- 与 v1 工作流一致(纯代码 / git diff 友好 / grep 可定位)
- Qt Designer 的拖拽收益要在"非程序员协作 / 50+ 字段密集表单 / 快速对比 5 种布局"才显现,本项目都不沾

**代码组织:v2.1 收窄后**

```
control_panel_pyside/
├── __init__.py
├── __main__.py            # 入口:QApplication + 主题 + 主窗口装配
├── main_window.py         # QMainWindow + QSplitter(主区/侧栏) + QTabWidget(3 页)
├── theme.py               # PyQtDarkTheme/hanaarashi 封装 + 主题持久化
├── polling.py             # 轮询基础设施(v2.1 仅 git status 走异步通道)
├── cli_invoke.py          # subprocess 封装 + QThread 异步
├── views/
│   ├── __init__.py
│   ├── _base.py           # _BasePage(QWidget):标题栏 + QScrollArea 模板
│   ├── status.py          # 状态页(合并 v2.0 overview/doctor/guard,见 §7.8)
│   ├── changelog.py       # 变更页(读 CHANGELOG.md,见 §7.9)
│   └── tasks.py           # 任务页(保留 v2.0 设计,见 §7.7)
└── widgets/
    ├── __init__.py
    ├── doc_sidebar.py     # 关键文档常驻侧栏(见 §7.10)
    └── debug_dock.py      # 底部折叠调试输出(见 §7.11)
```

**v2.1 删除的文件**:`views/{ai,events,history,sync,overview,doctor,guard}.py` × 7 + `conclusion_panel.py` × 1。

**约束**:
- 每个 `views/*.py` 不超过 300 行;超出说明该页职责过重,拆子组件
- 业务判断只在 model 层(已有 `harness/control_panel_model.py`),views 只做"调 model → 渲染 dict";变更页是例外(纯文本展示,不走 model)
- `_base.py` 的 `_BasePage` 提供:标题栏 widget + 内嵌 QScrollArea + 一个 `refresh()` 抽象方法

### 7.2 信号槽连接风格

**混合策略**:同文件内用 lambda,跨文件 / 跨类用 `@Slot()` 装饰器。

**lambda(同文件简单连接)**:

```python
btn.clicked.connect(lambda: self._refresh())
combo.currentTextChanged.connect(lambda v: self._on_theme_changed(v))
```

**@Slot()(跨文件 / 需调试栈 / 需类型检查)**:

```python
from PySide6.QtCore import Slot

class OverviewPage(_BasePage):
    @Slot(dict)
    def on_polling_event(self, event: dict) -> None:
        # 跨文件信号(polling.py 发的)用显式 slot
        # 好处:堆栈里看得到方法名,IDE 能跳转
        ...

# polling.py
self.event_received.connect(overview_page.on_polling_event)
```

**详细信号清单**(Phase 2 开工时填):
- `polling.PollingService.event_received(dict)` → `views/*.refresh(event)`
- `theme.ThemeManager.theme_changed(str)` → `MainWindow._apply_theme()`
- `theme.ThemeManager.theme_changed(str)` → `MainWindow._refresh_all_icons()`(qtawesome icon 主题切换不自动重绘,需主动重建,见 §7.4)
- `MainWindow.tab_changed(int)` → `ConclusionPanel.switch_to(idx)`

**为什么是 Qt Signal(不是 Python callback)**:跨文件传 dict(polling → views 跨潜在线程边界),Qt Signal 自带 queued connection 跨线程安全;Python callback 要自己处理线程切换(`QMetaObject.invokeMethod` 或 `QTimer.singleShot(0, ...)`)更易出错。

### 7.3 主题方案(PyQtDarkTheme + 局部 QSS)

**主体策略**:`PyQtDarkTheme` 兜底现代外观,无需 QSS 手写工作。局部需要的微调(卡片圆角、状态色块)叠 QSS 覆盖。

**API 用法**(一行切主题):

```python
import qdarktheme

# main.py 启动时
app = QApplication(sys.argv)
qdarktheme.setup_theme("auto")   # auto / dark / light;auto 跟随系统
# 用户运行时切换:
qdarktheme.setup_theme("dark")   # 重新调用即可
```

**深/浅切换 UI 入口**:右上角菜单 `View → Theme → Auto/Dark/Light`,选项写入 `~/.claude/control_panel_pyside.json` 持久化,启动时读回。

**局部 QSS 微调点**(Phase 4 开工时确认):

- 状态卡片(总览页绿/黄/红条):用 QSS 设 `border-left: 4px solid <color>`
- 事件列表行高:`QListWidget::item { padding: 6px; }`
- 结论面板代码块:`QTextEdit { font-family: "JetBrains Mono"; }`

**不做**:不写整套 QSS 主题文件(那是 PyQtDarkTheme 的活);不引入 `qt-material` / `qdarkstyle` 等同类竞品。

### 7.4 图标方案(qtawesome)

**字体图标库**(免去维护 .png 资源):

```python
import qtawesome as qta

# 用法
btn = QPushButton(qta.icon("fa5s.sync"), "同步")
tab.addTab(page, qta.icon("fa5s.heartbeat"), "守护")
```

**图标取色**:`qtawesome` 创建 icon 时锁定颜色(取自当时的 palette)——**不会随主题切换自动反色**。运行时切主题(V7 要求)需主动重建已挂载的 icon。

**主题切换时的 icon refresh 流程**:

```python
class MainWindow(QMainWindow):
    def __init__(self):
        ...
        self._tab_icons: dict[int, str] = {0: "fa5s.tachometer-alt", 1: "fa5s.tools", ...}
        theme_mgr.theme_changed.connect(self._refresh_all_icons)

    @Slot(str)
    def _refresh_all_icons(self, theme: str) -> None:
        # 重建所有 tab icon(qtawesome 会取当前 palette 的新色)
        for idx, icon_name in self._tab_icons.items():
            self.tabs.setTabIcon(idx, qta.icon(icon_name))
        # views/* 内部如有 icon,也通过 signal 通知各自重建
```

**图标集选用**:Font Awesome 5 (`fa5s.*` 实心 / `fa5r.*` 线性),覆盖度足够 7 页签所需。

### 7.5 启动性能(按形态分预算)

| 形态 | 冷启预算 | 构成 |
|---|---|---|
| **`.bat` 直跑(开发期)** | < 1.5s | PySide6 import ~400-700ms + PyQtDarkTheme setup ~50ms + 业务初始化 ~500ms |
| **`.exe`(PyInstaller `--onefile`)** | < 5s | 上述 + onefile 解包临时目录 ~1-2s + 首次 Win Defender 扫描 ~1s |
| **`.exe`(PyInstaller 目录形态,非 onefile)** | < 2s | 上述基础不解包,接近 .bat |

**结论**:开发期(.bat)用 1.5s 预算;发布期(.exe `--onefile`)预算放宽到 5s,与 §8.2 配置一致。如要 .exe 也接近 1.5s,可改 PyInstaller 目录形态(放弃单文件分发便利换启动速度)。Phase 4 实测后定。

### 7.7 任务总览页(v2 新增,需求 §4.1)

**职责**:展示 active + archived 任务清单 + 简介 + stage 标识。点卡片:弹出该任务目录(系统文件管理器) + 在右侧结论面板显示长版简介。

**数据源**:`harness_status.py --tasks --json`(harness-governance-v1 Phase 2-A.1 已交付)。**v2 不重复实现**任务扫描 / 简介抽取 / stage 解析逻辑——这些已在 CLI 端做完。

**JSON 契约**(实测 `python harness_status.py --tasks --json` 输出):

```jsonc
{
  "active": [
    {
      "name": "control-panel-v2-pyside",
      "stage": "discussion",       // discussion / implementation / unknown
      "brief": "把 control-panel-v1 的 Tkinter GUI...",  // 自动从 §1 抽取
      "path": "D:/ClaudeTasks/active/control-panel-v2-pyside"
    },
    ...
  ],
  "archived": [...]   // 同结构
}
```

**简介抽取规则**(harness_status.py 端实现,v2 直接用):优先级 `需求分析.md §1` > `HANDOFF.md §30 秒速读` > `SPEC.md` 头段 > `(无简介)`。**v2 不维护新字段**。

**UI 布局**(`views/tasks.py`):

```
QVBoxLayout(整页)
  ├─ QHBoxLayout(顶部工具条)
  │    ├─ QLabel("任务总览")
  │    ├─ QLabel("active: N | archived: M")(右对齐)
  │    └─ QPushButton(qta.icon("fa5s.sync"), "刷新")
  ├─ QLabel("Active")
  ├─ QScrollArea
  │    └─ QGridLayout (3 列卡片)
  │         └─ TaskCard(QFrame) × N
  ├─ QLabel("Archived")
  └─ QScrollArea
       └─ QGridLayout (3 列卡片) × M
```

**TaskCard 结构**:

```
QFrame(setObjectName="task-card",QSS 圆角 + 边框 + hover 高亮)
  └─ QVBoxLayout
       ├─ QHBoxLayout(标题行)
       │    ├─ QLabel(任务名,粗体)
       │    └─ QLabel(stage 徽章,QSS 染色:discussion=蓝/implementation=绿/unknown=灰)
       ├─ QLabel(brief,wordWrap=True,最多 3 行)
       └─ (无按钮,整张卡片 mousePress 触发 task_clicked 信号)
```

**信号清单**(补充到 §7.2):
- `TaskCard.clicked(str)` (任务名) → `MainWindow._on_task_card_clicked()`
- `MainWindow._on_task_card_clicked()` 双动作:
  - `subprocess.Popen(["explorer", task_path])`(Windows)/`xdg-open`(Linux)打开任务目录
  - `conclusion_panel.show_task_brief(name)` 在右侧渲染长版简介(读取 `需求分析.md` / `HANDOFF.md` 完整 §1)

**刷新策略**:
- 切换到任务页时自动拉一次(在 `tasks_page.showEvent()`)
- 用户手动点"刷新"按钮触发
- **不轮询**——任务列表变化频率低(创建 / 归档都是人为动作),轮询无意义

**异步执行**(避免主线程卡):
- `cli_invoke.run_async([...harness_status.py, --tasks, --json], on_done=callback)` 走 QThread
- 加载中卡片区显示 spinner(`qta.icon("fa5s.spinner", animation=qta.Spin(...))`),数据回来后替换

**错误处理**:
- CLI 返回非 0 → 顶部红条 banner "harness_status.py --tasks 执行失败,见日志"
- JSON 解析失败 → 同上
- 不抛 exception 到 UI 线程

**抽取规则**:每条记录以 `### [YYYY-MM-DD HH:MM]` 开头,直到下一条 `### [` 之前。`Path.read_text(encoding="utf-8")` 后正则切分,取顶部 N 段(默认 N=20,可配置)。

## 8. 打包与分发(PyInstaller)

### 8.1 开发期依赖装载

```
control_panel_pyside/requirements.txt
  PySide6==6.x.x
  PyQtDarkTheme==2.x.x
  qtawesome==1.x.x
```

`.bat` 启动时:

```bat
@echo off
pip install -r requirements.txt --quiet
python -m control_panel_pyside
```

`--quiet` 让已装依赖不刷屏,缺依赖才输出。不用 `pyproject.toml`(个人项目用不上 build/publish 元数据)。

### 8.2 一键打包 .exe

**目标**:双击 `control_panel_pyside.exe` 即用,免安装 Python。

**spec 配置策略**:

```python
# control_panel_pyside.spec(Phase 5 开工时落地)
a = Analysis(
    ['control_panel_pyside/__main__.py'],
    hiddenimports=['qdarktheme', 'qtawesome'],  # 避免动态 import 漏打包
    excludes=['tkinter', 'unittest', 'test'],   # 减体积
    ...
)
exe = EXE(..., name='control_panel_pyside', console=False)
```

**关键参数**:

- `--onefile`:打成单 .exe,**启动 3-5s**(解包到临时目录 + PySide6 import + Win Defender 扫描),便于分发(单文件可拷贝)
- `--windowed`:不弹 console
- 不签名(个人自用,Win Defender 第一次会提示,可手动放行)

**启动速度 vs 分发便利的取舍**:
- onefile(默认选用):**3-5s 冷启**,U 盘 / 邮件附件友好
- 目录形态(`pyinstaller spec` 不加 `--onefile`):**< 2s 冷启**,产物是文件夹(几百个文件),分发要打包成 zip
- Phase 5 实测后按个人使用偏好选;若 .exe 启动慢到难忍,切目录形态

**预期体积**:80-150 MB(PySide6 占大头)。瘦身路径(后续可选):`--strip` / 改 Nuitka / 用 PySide6-Essentials 子集。Nuitka 对 PySide6 体积优势可观(30-50%),但本期优先生态成熟度,推迟到 Phase 5+。

**构建命令**:

```bat
pyinstaller control_panel_pyside.spec
:: 产物在 dist/control_panel_pyside.exe
```

**与开发期 .bat 共存**:开发改代码用 `.bat` 直跑;发布版本时跑一次 `pyinstaller` 出 .exe。
