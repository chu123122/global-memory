# Requirements · control-panel-v1

> 文档类型：需求分析
> 创建：2026-04-24
> 任务目录：`projects/control-panel-v1/`
> Status: implementation

## 1. 背景和痛点

global-memory 已经有很多维护脚本：健康检查、同步、hook、daemon、AI adapter、文档校验。问题不是没有工具，而是工具分散，维护者很难一眼知道：

- 现在仓库健康不健康。
- 自动同步到底有没有在跑。
- 当前改动如果同步，会被提交成什么。
- 哪个按钮只是查看，哪个按钮会修改、提交或推送。
- AI 如果参与维护，怎么把状态反馈给人类，而不是只留在终端输出里。

因此需要一个 **人类主控入口**。它不替代 Claude/Codex，也不做复杂 IDE；它的定位是把现有 harness engineering 工具收束成可视化、安全、可解释的桌面面板。

## 2. 目标

V1 的目标是：维护者双击 `harness\control_panel.bat` 后，能在 3 分钟内回答四个问题：

1. 当前仓库有没有变更、是否 ahead/behind、daemon 是否运行。
2. 当前维护体系健康检查是否通过。
3. 当前变更如果同步，会形成什么 checkpoint。
4. AI 或外部脚本有没有发来需要人类注意的事件。

## 3. 范围

### 3.1 本轮已经纳入

| 能力 | 要求 |
|---|---|
| 主控 CLI | `maintain.py` 统一 `status / doctor / fix / sync / daemon / log / report`。 |
| 只读状态 | `status --json` 和 `sync --preview --json` 不改变 tracked 文件。 |
| GUI | 中文 Tkinter 面板，支持总览、修复、同步、守护、AI、事件、历史。 |
| 实时性 | 面板每 10 秒静默刷新快速状态，每 2 秒读取外部事件。 |
| 外部事件 API | `panel_api.py notify` 写入本地 JSONL，面板自动显示。 |
| AI 安全边界 | V1 只允许诊断和计划，`execute` 模式明确拒绝。 |
| 文档 | README、MAINTENANCE、CONTROL_PANEL 和本任务文档说明用法与边界。 |

### 3.2 暂不纳入

- 不引入 PySide、Web 前端、FastAPI、Flask 或数据库。
- 不开放 HTTP/WebSocket API。
- 不内嵌交互式 Claude/Codex 终端。
- 不让 AI 自动修改仓库文件。
- 不做完整 Phase 4 任务中心和策略配置页。

## 4. 验收标准

| # | 标准 | 验证方式 |
|---|---|---|
| V1 | `maintain.py status --json` 输出 Git、daemon、最近提交和日志摘要。 | CLI 运行并检查 JSON 字段。 |
| V2 | `maintain.py sync --preview --json` 只读生成 checkpoint 候选摘要。 | 前后 `git status --short` 完全一致。 |
| V3 | GUI 左侧所有页签内容可滚动，鼠标滚轮可用。 | 打开 GUI 手动验证。 |
| V4 | GUI 自动静默刷新状态，不刷屏。 | 打开 GUI 等待 10 秒，状态卡片更新，输出区不增加刷新噪音。 |
| V5 | 外部事件能显示到面板。 | 运行 `panel_api.py notify`，事件页和输出区出现消息。 |
| V6 | AI execute 被拒绝。 | `ai_runner.py --mode execute --json` 返回 2 和明确错误。 |
| V7 | 健康检查通过。 | `doctor`、`smoke_test`、`bootstrap check`、`check_health` 通过。 |
| V8 | 新文档不被误判为孤儿。 | `verify_memory.py` 和 `check_health.py` 不报新文档错误。 |

## 5. 风险和边界

| 风险 | 影响 | 处理 |
|---|---|---|
| Tkinter UI 能力有限 | 不如 Web/PySide 漂亮 | V1 先无依赖可用，后续再迁移。 |
| 文件型事件 API 不是强实时 | 有 2 秒轮询延迟 | 可接受；换来无端口、无常驻服务。 |
| 面板自动刷新和用户手动操作冲突 | 状态栏/输出区被打扰 | 自动刷新走 quiet 模式，不写输出区。 |
| `panel_api.py` 写入用户目录日志 | 不进入 Git，可能积累日志 | 后续可加清理或轮转。 |

## 6. 后续方向

- 增加事件过滤、清空和按 level 着色。
- 把维护报告做成 GUI 结构化卡片，而不只是文本输出。
- 若 V1 稳定，再评估 PySide6 或本地 Web UI。
- 若确实需要外部 API，再基于明确需求增加本地 HTTP 服务。
