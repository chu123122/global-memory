## Diagnosis

按"理解成本/视觉冲击"由高到低排序。每条都给出 file:line 与 V编号 对应。

### P0（首屏致命）

**P0-1 `section_card` 黄边 + 黄底一锅炖（V1 + V4）**
`theme.py:217-225` 的 `QFrame#section-card / QFrame#task-card` 在 hanaarashi 下**完全共用同一条 QSS 规则**——`background: bg_card (#f3ede4)`、`border-left: 3px solid accent_aka (#c47b6b)`。结果：
- 主区结论卡 / Git 卡 / Daemon 卡 / Doctor 卡（`status.py:98-131` 全部 4 张卡）= 同一外观
- 右侧 `DocSidebar` 的 6 个文档跳转按钮的容器 `QFrame#doc-sidebar` 没有自己的样式（`doc_sidebar.py:34`），**继承全局 `QFrame` 默认 + 内部按钮样式**——但用户看到的是按钮密集排布出的"卡阵"，与主区视觉权重 1:1
- 没有任何"hero / body / weak"分级机制

**P0-2 一键修复 primary 按钮在 hanaarashi 下显示成灰边框（V2）**
`theme.py:287-291`：
```css
QPushButton[role="primary"] {
    background: {p['accent_blue']};   /* #7b9bb5 灰青 */
    color: #fffdf9;
    border-color: {p['accent_blue']};
}
```
QSS 规则**本身正确**，但 `QPushButton:hover` 规则（`theme.py:297-301`）写在 `[role="primary"]` 之后**且选择器特异性相同**——QSS 后写的覆盖先写的，所以鼠标一移过去就被 `:hover` 的 `bg_card` 米色覆盖盖掉了 primary 的灰青。即使不 hover，primary 视觉权重 = secondary（都是 1px border + 浅底），看着像 disabled。

**根因**：选择器特异性 + 顺序问题。`QPushButton[role="primary"]:hover` 没单独写，所以 `QPushButton:hover` 接管。

**P0-3 字号无层次（V6）**
- `_BasePage` 标题 `QFont("", 13, Bold)`（`_base.py:42`）
- `section_card` 标题 `QFont("", 11, Bold)`（`components.py:21`）
- `decision-headline` 没设字号，继承全局 `font-size: 11pt`（`theme.py:163`）
- 整窗只有 11pt-13pt 两档，**结论卡 hero 字和子系统卡内文字一样大**

### P1（布局浪费 / 信息密度低）

**P1-1 4 张卡纵向堆叠 + 结论卡 2 行字占 50% 高度（V3）**
`status.py:79-131` `_build_content` 顺序：toolbar → 结论卡 → Git 卡 → Daemon 卡 → Doctor 卡 + 6 行明细。每张卡用 `section_card` 的 `QVBoxLayout(margins=16,14,16,14, spacing=8)`，加上 `_base_page` 的 `spacing=10`，4 张卡纵向至少 `4 × 80px = 320px`，1180×760 窗口去掉 toolbar+tabbar+statusbar+debug-dock-collapsed 后实际可见区 ~600px，**Doctor 卡 + 6 行 check 明细必然出屏**。

而结论卡只放 `headline + next_step` 两行 QLabel，竟和 Git/Daemon/Doctor 同等卡片框，视觉上**没体现"这是 hero"**。

**P1-2 Doctor 6 项 check 永远展开（信息噪音）**
`status.py:127-131` 把 6 个 `CHECK_LABELS` 永远 addWidget 进卡内，初始全是 `"git_status：—"` 占位。日常用户根本不需要逐项看；只有 ERROR 时才需要展开看是哪项。

**P1-3 Tab 头部 title + subtitle 重复一行（V7）**
`_base.py:36-49` 每个页面顶部 `QFrame#page-header` 用 `margins=14,10,14,10` 渲染 title (13pt bold) + subtitle (灰)，吃 ~50px。但 `QTabWidget` 的 tab bar 已经显示了"状态/健康/变更/任务/诊断"——`title="今日状态"` 和 tab 名"状态"完全重复信息。subtitle "看头条结论 + 下一步即可" 是给开发者看的注解，日常用户每次启动都被它抢一行。

**P1-4 侧栏 6 卡片视觉权重 = 主区（V4）**
`doc_sidebar.py:46-56`：6 个 `QPushButton`（带 qta 图标 + 文字 + secondary role），FixedWidth=220。在 hanaarashi 下按钮样式（`theme.py:278-301`）= `bg_input + 1px border + padding 7px 14px + min-height 30px`，与主区 `[一键修复] / [刷新]` **完全同款**。视觉权重 1:1。

**P1-5 健康页用 emoji + role 双套视觉语言**
`health.py:23-29` `STATUS_META` 用 `🔴🟡🔵🟢`，状态页用 `decision-headline[role="..."]` 染色。两 tab 同窗共存 = 用户每切换一次要重新建立颜色映射。

### P2（细节 / 主题风味）

**P2-1 hanaarashi 主题"日式文学"风味未落地**
- `theme.py:152` 声明用 `Shippori Mincho` 衬线字体作为标题，但**只用在 tab bar 和 dock title**（`theme.py:206, 351, 386, 405`），主区所有 QLabel 都是 sans-serif（`bg_base body` 在 `theme.py:160-162`）
- 结论卡 headline 没用衬线，没体现"文学性"
- 状态栏右下角 `whisper` 设了 8% 透明度（`main_window.py:142-143`），但只是固定字符串"春の花びらが風に散る"——可以做"按 severity 切换俳句"
- `border-radius: 8px` 偏现代 SaaS 风，与日式审美的"硬直、留白"不符
- 卡片左边那条 3px `accent_aka` 红线在每张卡都出现 → 红线本应是"重点强调"标志，全用了等于没用

**P2-2 自动刷新闪烁（health 页 D7 残留）**
`health.py:106-120` `_render_cards` 每 30s 全部 `deleteLater()` + 重建 widget。状态页虽然 in-place 更新 QLabel，但 doctor 6 行 check 详情每次 `setText()` 也会触发 layout 重算（因为字数可能变）。

**P2-3 默认窗口 1180×760 太窄**
`main_window.py:91`，splitter 给主区 960、侧栏 220。主区 960 - margins(14×2) = 932px 宽，要塞 4 张子系统横排（每张 ~220px）有点紧。建议默认 1280×800，最小 960×600。

## Primary User Flow

**理想流程（5 秒）**

```
T+0s   双击 .bat
T+1s   窗口出现，默认状态页
T+2s   眼睛锁定主区顶部最大字（结论 headline）
T+3s   颜色 + 一行字告知：绿=没事/黄=要看一眼/红=要动手
T+4s   若黄/红 → 视线下移看 next_action 那行 CLI
T+5s   要么 [关窗]，要么 [Win+R cmd 执行 CLI]
```

**当前实际流程在哪步失败**

| 步 | 现状 | 失败点 |
|---|---|---|
| T+2 | 主区第一眼看到 6 张同色黄卡片 | **没有视觉锚点**——眼睛不知该看哪 |
| T+3 | 所有卡都是同款黄边 | 看不出哪张是"结论"，哪张是子系统 |
| T+4 | next_action 字号 = body | 用户必须**主动读**而非"被吸引"，决策成本 > 5s |
| T+5 | [一键修复] 看着像灰按钮（disabled 错觉） | 用户产生"是不是坏了"的犹豫 |

**结论**：当前流程在 T+2 就失败。**首屏必须有唯一一个"视觉重心"**，且该重心 100% 等于结论卡。

| `body` | 11pt | Noto Sans SC | 子系统卡 summary、子系统名 |
| `caption` | 9pt | Noto Sans SC | "上次检查 12s 前"、tab 副标题（如保留） |

#### 卡片样式分级

- **结论 hero**：**无 border、无 background、无 radius**——纯文字 + 一个 12px 圆点 indicator + 一条 hairline divider 隔开 next_action。这是"纸上写字"的感觉
- **子系统卡**：4 个横排 cell，**无边框**，仅靠列距 + 顶部一行 caption "── 子系统 ──"区分。每个 cell = 圆点 + 名字 + 一行 summary
- **侧栏**：默认**完全隐藏**，菜单 `视图 → 关键文档` 切换；展开时也只用 `QListWidget` 列文件名（无图标无按钮）

#### 与花と嵐主题关系

最契合。"留白即主角"是日式美学核心。但**实施风险**：用户对"什么都没有"的接受度未知，可能觉得太空。

| 级别 | objectName | 视觉 |
|---|---|---|

| **body**（子系统 4 卡） | `subsystem-cell` | bg=`paper-card`, border=1px solid `divider`, **border-left=3px solid sev色**, radius=2px, padding=12px 14px, fixed-height=88px |
| **weak**（侧栏） | `doc-sidebar-item` | 完全无 border、无 bg，仅文字 + qta 小图标 12px 高，hover 时 bg=`paper-card`。整个侧栏宽度从 220 → 180 |

#### 与花と嵐主题关系

- 衬线 hero 字 = 报纸大字标题，**真正用上 Shippori Mincho**
- `radius=2px` 而非 8px，体现日式硬直感（茶室直角）
- 留白：hero 卡 padding 24px 28px，比 SaaS 默认 16px 大
- accent_aka 红色**只出现在 hero 卡左边（且根据 severity 切换颜色）**和 tab 选中下划线——稀缺出现的红 = 真正强调
- 状态栏耳语扩展为 4 句轮播：`春の花びらが風に散る`（ok）/ `静寂の中で何かが動く`（info）/ `風雲急を告げる`（warning）/ `嵐が来る`（error）——和 severity 联动

## Interaction Rules

### R1 · primary 按钮高亮（修 V2 / P0-2）

**根因**：QSS 选择器特异性问题——`QPushButton:hover` 覆盖 `QPushButton[role="primary"]` 的 background。

**修复**（`theme.py` hanaarashi qss）：

```css
/* 必须显式声明 primary 的 hover/pressed/disabled，否则被通用 :hover 覆盖 */
QPushButton[role="primary"] {
    background: {accent_aka};        /* 改用 accent_aka 红，比 accent_blue 灰青更显眼 */
    color: #fffdf9;
    border: 1px solid {accent_aka};
    font-weight: 600;
}
QPushButton[role="primary"]:hover {
    background: #b56a5a;             /* 比 accent_aka 深 8% */
    border-color: #b56a5a;
    color: #fffdf9;                  /* 防被通用 :hover 的 accent_aka 颜色覆盖 */
}
QPushButton[role="primary"]:pressed {
    background: #a05a4d;
}
QPushButton[role="primary"]:disabled {
    background: #d8c4be;
    color: #faf0ec;
    border-color: #d8c4be;
}
```

**关键 QSS 属性**：
- `[role="primary"]:hover` 必须**单独写**，不能依赖通用 `QPushButton:hover`
- `font-weight: 600` 给 primary 多一层视觉权重（即使色弱用户也能识别）
- 4 主题（auto/dark/light/hanaarashi）都要补一组 `[role="primary"]:hover` 选择器，但 dark/light 用 `palette(highlight)` 做 hover 颜色（比基础色暗 12%），hanaarashi 用固定 hex

**dark/light/auto 主题**（在 `_base_card_qss()` 内补）：

```css
QPushButton[role="primary"] {
    background: palette(highlight);
    color: palette(highlighted-text);
    border: 1px solid palette(highlight);
    font-weight: 600;
}
QPushButton[role="primary"]:hover {
    background: palette(dark);     /* 比 highlight 暗 */
    border-color: palette(dark);
    color: palette(highlighted-text);
}
```
