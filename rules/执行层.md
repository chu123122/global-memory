# 执行层规格

> 同构骨架：定位 → 职责边界 → 接入 → 接出 → 本层细则 → 引用铁律 → 强制点。
> R 编号权威 = `../RULE_ENFORCEMENT_MATRIX.md`（条文↔强制点 + claude_rule_id 映射）。

## 定位

四层里**唯一含判断**的层（判断主体 = 执行 AI + 人）。把任务从"开工"推到"验收通过"。外三层（沉淀/反馈/维护）是纯契约，本层是活的。

## 职责边界

### 做
- **任务推进**：读上下文 → 定成功判据 → 循环到验证通过。
- **code review 分级**：按 Tier 0-3 决定验证强度（细则见下）。
- **TDD 执行**：改代码必有测试或替代验证；bug fix 先写复现失败测试。
- **恢复执行**：构建/测试/部署失败时按铁律 R9 边界恢复（只改输入不改环境）。
- **路由判断**：按耦合度决定主模型直跑 or 派 subagent。

### 不做
- 不沉淀知识（写记忆 = 沉淀层；本层只**触发**）。
- 不自评质量（铁律 R14）。
- 不造召回/不改反馈层注入。
- 不碰维护层观测（本层只产 diff 留痕，不读自己的健康报表）。

## 接入流程（怎么进本层）

```
/work [任务] → work_context_pack.py（硬启动，写执行证据）
  → 读 core/HANDOFF.md + core/STATUS.md
  → 新任务意图? → intent_guard 闸 → create_task.py
  → 输出"上次进度 X，本次继续 Y?" → 等用户确认
  → 绑 session task（--write-status，本终端私有）
```

脚本不可用 → 回答开头声明 `/work context pack 未运行`，不假装读过。

## 接出流程（怎么出本层 → 触发下游）

```
产物落 task 目录（core/design/ops/test）+ diff 留痕
  → ops/CHANGELOG.md append（PR/commit 级，当场记不攒）
  → 触发沉淀层：盲区/bug/记住 → 沉淀层触发表（见 沉淀层.md）
  → 跨天/中断 → 更新 core/HANDOFF.md「下次开始」
  → 收尾 task_complete.py --fix
```

本层**不直接写记忆库**——只在产物里留信号，由沉淀层规格定怎么入库。

## 本层细则（折自旧 CLAUDE.md，非铁律）

| 细则 | 内容 | 旧来源 |
|------|------|--------|
| **code review 分级** | Tier 0/1 记验证说明；Tier 2 测试证据 + correctness/test-quality 审查；Tier 3 四视角 + 人工裁决 + 回滚说明。AI review 不替代确定性检查。 | 旧 CLAUDE 代码质量门 + `../QUALITY_GATE.md` |
| **启动协议** | 正式任务（>3 轮 或 改文件）：读 MEMORY → HANDOFF → 核进度 → 确认再动；快速提问直接答；非技术请求通用助手模式。 | 旧 CLAUDE 启动协议 |
| **TDD 记录** | Red（失败命令+原因+为何符合预期）→ 最小实现 → Green（通过命令+摘要）→ 写回 Phase 卡 + test/测试.md。后补测试不算 TDD。 | work SKILL Step 3 |
| **路由细则** | 高耦合（编译循环/多文件关联/设备排查）→ 主模型；低耦合（grep/git摘要/独立文档）→ subagent。歧义→主模型。 | 旧 CLAUDE Lane + work SKILL |

> 阈值/脚本实现（subagent 预算数字、轮数阈值、Lane 判定矩阵全文）不在本规格，下沉对应 script 旁（操作即文档）。

## 强制点（哪条被哪 hook 以什么强度强制）

见 `../RULE_ENFORCEMENT_MATRIX.md`（条文↔强制点映射表）。本层相关：
- 文档齐全度 → `doc_gate.py`（S1 硬阻断编辑）
- 大文件读 → `read_large_file_guard`（S2 软校验）
- subagent prompt 质量 → `agent_prompt_gate`（S1 ask）

### doc_gate 双层协同（从 work SKILL 移入）

文档齐全度走**两道**，共享 `project_registry.json` 单一源：
- **主动**：skill 入口（work Step0/收尾）主动校验 → 提前预警。
- **被动**：`doc_gate.py` PreToolUse 编辑时拦截 → 兜底。

行为：registry sanity 失败 → doc_gate 输出 warning 继续 per-task 检查；当前文件匹配的 task 文档不全 → 阻断该次编辑；不匹配任何 task → 放行。
机制实现（registry 字段 / tasks_root / 3 脚本跟进）= 操作细则，下沉 script 旁，不在本规格。
