## 2. 技术风险 — 🔴 BLOCK

**发现**：
- **双轨同名脚本（M-02）**：`scripts/` 与 `skills-repo/_bootstrap/scripts/` 各有一份 `task_complete.py`、`verify_memory.py`、`sync_index.py` 等 ~22 个同名文件。`task_complete.py:37-40` 用 if-fallback 隐藏了这个问题，但**任何一边的修复都不会同步到另一边**。下一次 fix bug 时几乎必然出现"修了一份没修另一份"
- **跨电脑可移植性**：`fix_hardcoded_paths.py` 还在维护 `D:/global-memory` → `~/.claude/global-memory` 的映射，说明历史残留路径污染未根除；`hooks.bak.20260416135033/spec_gate.py:13` 仍硬编码 `D:/skills-repo/_bootstrap/templates`
- **MEMORY.md 索引漂移（M-01）**：实际文件数约 64，索引声明 49/50。verify_memory.py 设计了 MEM-11 孤儿检测，但 04-14 时是 PASS，说明检测逻辑未覆盖 docs/、test-reports/、retrospectives/ 等子目录——验证脚本本身有盲区
- **`skills/work/` 是孤儿目录（M-03）**：repo 中没有源，只在部署位存在，下次 `git pull skills-repo` + 重新部署会被丢失
- **CLI auto-memory（M-04）**：CLAUDE.md 严格禁用但 CLI 仍在写，3 天前还在更新——这是 P0-1 假修复

**建议**：
- 立即定一边为源（建议 `skills-repo/_bootstrap/scripts/`），另一边改 symlink；写一个一次性脚本 `assert_no_drift.py` 检查同名文件 hash 一致
- 把 `hooks.bak.*` 目录搬到 `~/.claude/_archive/`
- verify_memory.py 的孤儿检测必须递归扫到所有子目录，目前显然漏了
- CLI auto-memory：要么在 `~/.claude/settings.json` 真正关闭，要么承认双轨并定义清晰边界（CLI memory = 会话临时缓存，session 结束自动清空；global-memory = 持久化）。当前"承诺禁用、实际放任"是最差选项

  - **方案 A（保留现状 + 补承载）**：补全 hook、补 FILE-01 脚本、补孤儿检测——工作量大但保留架构
  - **方案 B（瘦身）**：删 archives/、access_count、changelog_archive，把 conventions 🔒 缩到真正能自动检查的 8 条；把 skills 减到 3 个核心（work / check / skill-creator）

- 取舍倾向：方案 B + 方案 C 组合。瘦身 + 单源，能消除约 60% 的双轨/漂移问题
