# 学习方法论：从"学了"到"面试讲出来"

> 生成日期：2026-04-13
> 用途：解决"看了很多但面试答不好"的根本问题
> 背景：心动三面 Subsystem 不知道（看过但忘了）、米哈游系统设计说不清楚（做过但讲不出来）

---

## 一、诊断：链路断在哪

```
看文章/源码 → [记忆断点] → 记住了 → [表达断点] → 面试讲出来
               ↑                          ↑
            问题 1                      问题 2
```

### 问题 1：看了但记不住

- **根因不是记忆力差，是没有输出**
- 只做了输入（读），没做输出（写/说/做）
- 认知科学结论：**没有检索练习的学习，遗忘率在 24 小时后达到 70%**
- 看了 Subsystem 的文章，点头"懂了"，但从来没合上文章尝试从头默写流程
- 所以面试时想不起来

### 问题 2：做过但讲不出来

- **根因是没有预排练过口头表达**
- 写代码和讲代码是完全不同的认知通道
- 做了帧同步 v2，对每个模块了如指掌，但从来没对着录音讲过"这个系统怎么设计的"
- 面试时第一次开口组织语言 = 实时翻译，必然卡顿

## 二、AESR 四步法（核心框架）

每学一个概念（比如 UE Subsystem），强制走这 4 步：

| 步骤 | 做什么 | 时间 | 关键标准 |
|------|--------|:---:|---------|
| **A - Absorb（吸收）** | 读文章/源码，**只读一遍**，标记不懂的点 | 30min | 不要反复读同一篇 |
| **E - Extract（提取）** | 合上文章，用自己的话写一份笔记（**不看原文**） | 20min | 写不出来的地方 = 没真懂 |
| **S - Speak（表达）** | 假设面试官问你"XX 是什么"，**录音回答**，控制在 2 分钟内 | 10min | 回听录音，找卡壳的点 |
| **R - Recall（回忆）** | **3 天后**，不看笔记，再讲一遍 | 5min | 还能讲出来 = 真会了 |

**关键**：第 2 步和第 3 步才是真正学习发生的地方。第 1 步只是搜集原材料。

大多数人只做了第 1 步就以为学会了。

### 为什么有效

- **Extract 利用了"检索效应"**：主动回忆比被动重读，记忆保持率高 50-100%
- **Speak 利用了"生成效应"**：用自己的语言重组信息，比原文直接背诵记忆更深
- **Recall 利用了"间隔效应"**：3 天后的回忆强化了长期记忆通路

## 三、间隔重复系统（配合 AI 学习 Agent）

### 学习 Agent 配置建议

```
每次学完一个知识点后，学习 Agent 自动：
1. 当天：问一个关于这个知识点的面试题（触发第一次回忆）
2. 3 天后：问一个不同角度的问题（触发间隔回忆）
3. 7 天后：出一道需要组合多个概念的综合题（触发深度理解）
4. 如果答错/答不好 → 标记"需要复习" → 缩短下次间隔
```

本质是 **SRS（间隔重复系统）**，用面试题代替 Anki 卡片。

### 间隔时间表

| 回忆结果 | 下次间隔 |
|---------|---------|
| 完全讲出来（L5） | 当前间隔 × 2.5 |
| 大部分讲出来（L4） | 当前间隔 × 1.5 |
| 只记得大概（L3） | 重置为 1 天 |
| 完全不记得（L1-L2） | 重新走 AESR 全流程 |

## 四、知识掌握层级

| 层级 | 标准 | 测试方法 |
|:---:|------|---------|
| L1 认知 | 能说出这个概念是什么 | 一句话定义 |
| L2 理解 | 能解释为什么要这样设计 | "如果不用 XX，会怎样？" |
| L3 应用 | 能在代码中正确使用 | 手写一个最小示例 |
| L4 分析 | 能对比不同方案的 trade-off | "XX 和 YY 的区别？什么时候用哪个？" |
| **L5 表达** | **能在 2 分钟内清晰讲给面试官** | 录音回听，无卡顿 |

**面试需要 L4-L5。** 很多知识停在 L1-L2 就是面试崩的原因。

## 五、周计划模板

| 时间 | 周一 | 周二 | 周三 | 周四 | 周五 | 周末 |
|------|------|------|------|------|------|------|
| **新知识** | 读 1 个 UE 模块 | — | 读 1 个 C++ 概念 | — | — | 做 1 个技术 demo |
| **巩固** | — | 提取 + 表达（周一的） | — | 提取 + 表达（周三的） | 3 天前的回忆测试 | 写 1 篇博客 |
| **面试** | — | — | — | — | — | 模拟面试 1 次 |

### 新知识 vs 巩固比例：3:7

巩固时间应该是学新东西的 **2 倍以上**。之前的比例大概反了。

## 六、巩固方法对比

| 方法 | 效果 | 适合场景 | 投入 |
|------|:---:|---------|:---:|
| **录音讲解（S 步骤）** | ★★★★★ | 任何概念 | 10min |
| **写博客** | ★★★★☆ | 深度理解 + 构建表达 | 1-2h |
| **模拟面试** | ★★★★★ | 综合能力 + 压力下表达 | 30min |
| **教别人** | ★★★★★ | 最深层理解 | 不可控 |
| **刷题** | ★★★☆☆ | 算法 + 手感 | 30-60min |
| **重新读文章** | ★☆☆☆☆ | 几乎无效（错觉学习） | 浪费时间 |

### "重新读文章"为什么无效

- 心理学叫"流利性错觉"（fluency illusion）
- 第二遍读的时候觉得"都看过了"，产生"我会了"的假象
- 但被问到时仍然讲不出来，因为**没有建立主动检索的通路**

## 七、怎么判断"我真的掌握了"

### 自测三问法

对任何一个知识点，问自己：

1. **一句话定义**：能不能用一句话说清楚这是什么？
2. **为什么这样设计**：能不能说出设计的 trade-off？
3. **给面试官讲 2 分钟**：能不能不看笔记，流畅讲出来？

三个都能 → 真会了。任何一个不能 → 需要补对应层级。

## 八、针对 AI 工作系统的具体建议

### 学习 Agent 应该怎么配置

**正确做法**：
- 先让我自己尝试回答/讲解，Agent 只在我请求时才给解答
- 每次学完后自动出一道面试题（不是直接给答案，而是问我）
- 3 天后自动触发回忆检测
- 记录我的回答质量，标记需要复习的知识点

**错误做法**：
- Agent 直接给完整答案（喂答案模式，产生流利性错觉）
- 一次性灌输大量知识（没有间隔，全部遗忘）
- 只做 Absorb 不做 Extract/Speak（只输入不输出）

### 双 Agent 在学习中的分工

| 场景 | 用哪个 Agent | 行为 |
|------|------------|------|
| 学新概念 | 学习 Agent | 苏格拉底追问 → 引导自己发现 |
| 写面试话术 | 学习 Agent | 我先讲一遍 → Agent 点评 + 优化 |
| 做项目遇到不会的 | 工作 Agent | 直接给方案（工作场景效率优先） |
| 复习旧知识 | 学习 Agent | 出题 → 我回答 → Agent 评分 |
