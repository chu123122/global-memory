### 你的 CLAUDE.md 现状

你当前 24 行 → **符合最佳实践**（≤ 60 行范围内）。

### 每行的"石蕊测试"

> **删掉这行，Agent 会犯一个具体的、可观察到的错误吗？**
> - "不会" → 删掉
> - "会" → 保留

### 该放什么 vs 不该放

| ✅ 该放 | ❌ 不该放 |
|---------|----------|
| 非默认工具选择（`Use pnpm, not npm`） | 语言基础（Agent 已知） |
| 项目特定契约 | 框架惯例（默认如此） |
| 可执行的精确命令 | 通用建议（"Write clean code"） |
| 架构红线 | 目录列表（Agent 能 ls） |
| 代码从无法推断的惯例 | 项目综述（可从文件推断） |

### 你可以改进的地方

对照你的 CLAUDE.md（24行），做一次石蕊测试：

```
# 现有内容逐行评估
✅ "游戏客户端/引擎开发，C++/C#/Lua" → 保留（Agent 不读简历不知道）
✅ "短板：C++多线程/UE底层" → 保留（影响教学方向）
✅ "遵循项目已有命名约定" → 保留（防止 Agent 自作主张）
✅ "审查只报告不修复" → 保留（核心行为约束）
✅ "新对话启动协议" → 保留（实际解决了问题）
⚠️ "超15轮提醒/compact" → 可能多余（Agent 通常自己会管理）
✅ "修改记忆后必须在 CHANGELOG 追加" → 保留（硬性规则）
```

## 四、可借鉴的 Claude Code 设计

| Hook | 时机 | 可借鉴点 |
|------|------|---------|
| before_tool_call | 工具调用前 | 未来用 Claude Code 时可加 |

### 2. Memdir 记忆系统（你已有类似物）

| Claude Code | 你的系统 | 对齐度 |

**结论**：你的记忆系统设计和 Claude Code 的 Memdir 高度一致。

### 3. 6 大内置 Agent 协作（你是双 Agent）

## 五、你的系统 vs Claude Code 的差距

| 维度 | Claude Code | 你的系统 | 差距 |
|------|------------|---------|:----:|
| Prompt 分层 | 三层组装 | CLAUDE.md + Agent 配置 | 小 |
| 上下文管理 | 四层 + 三层压缩 | 四层记忆 + 手动 compact | 中 |
| 安全/权限 | 三层权限 + 沙箱 | 无 | 大（但个人无需） |
| 工具集成 | 6 Agent + Hook | 双 Agent + 20 脚本 | 中 |
| 记忆系统 | Memdir | global-memory | 小 |
| 验证体系 | 内置验证 | 4 个 verify 脚本 | 小 |

**一句话总结**：你的系统在个人使用场景下和 Claude Code 的 Harness 设计理念高度一致，主要差距在安全/权限层（个人不需要）和上下文压缩层（平台限制）。
