## 2. 新工具如何接入

### 2.1 加新 hook（进主循环）

1. 写 `harness/hooks/<name>.py`，**必 fail-open**（异常 silent return）。
2. PreToolUse 类：stdout JSON `{"decision":"block","reason":...}` 触发 BLOCK；UserPromptSubmit 类：stdout 即注入主模型上下文，控 token ≤200。
3. 注册 `harness/hook_manifest.json` 对应事件组：`path`(harness 内相对 .py) + `failure_action`(BLOCK|WARN|REPORT|NONE)。
4. 定插入顺序（PreToolUse：早=强阻断，晚=贴工具）。
5. 更 `hook-chain.md` 事件表 + `scripts-registry.md` §1。
6. `bootstrap.py install` 渲染进 `~/.claude/settings.json`。
7. `python harness/scripts/check_hook_alignment.py --strict --json` 校验对齐。

> 步骤 3-6 的多处手维护正是缺口#3 的痛点；`多数据源治理方案.md` M1 目标把它降为「改 manifest 一处 → reconcile --fix 全同步」。

### 2.2 加新普通脚本（不进主循环）

1. 写 `harness/scripts/<name>.py` 或对应子目录。
2. 登记 `capability_manifest.json`（core/optional/experimental/legacy/deprecated + 路径 + 能力归属）。
3. 登记 `scripts-registry.md`（用途行）。
4. 输出 JSON 的须进 output-contract（`verify_output_contracts`）。
5. `python harness/scripts/scan_orphan_scripts.py --strict --json` 对账（孤儿=0）。

### 2.3 接入即报错的旧痛点（缺口#3）

删/加 1 脚本 → 要手改 5 处（manifest + registry + capmap + README + docstring），漏一处巡检报红。
**目标**：单一全局索引 + 脚本启动自注册 / `--fix` 自动回填，巡检升级为检测 + 修复。**未实现**，当前仍手维护。框架方案见 `多数据源治理方案.md`。

## 3. 对账巡检（接入是否齐）

| 查什么 | 命令 |
|--------|------|
| 脚本能力是否被总览吸收 | `scan_orphan_scripts.py --strict --json` |
| hook manifest/文档/运行时是否漂移 | `check_hook_alignment.py --strict --json` |
| 能力边界是否清晰 | `check_capability_manifest.py --json` |
| 治理门禁 G1-G9 | `gate_check.py --json` |
