# Requirements · control-panel-v2-pyside

> 文档类型:需求分析
> 创建:2026-04-24
> 任务目录:`projects/control-panel-v2-pyside/`
> Status: implementation
> 上游任务:`control-panel-v1`(V1.2 Tkinter,已交付),本任务是 V2 重写

## 1. 这是什么

把 `control-panel-v1` 的 Tkinter GUI **整层重写为 PySide6**。**不改 model 层、不改 panel_api / maintain.py / ai_runner**——只换 view 层。目标:解决 Tkinter 滚动痛点 + 桌面级观感 + **降低用户使用主控台的认知负担**(2026-04-24 v2.1 收窄)。

**v2.1 范围收窄背景**(2026-04-24,本对话):用户实机使用 v2.0 后反馈"主控台复杂了,我引入它是为了减少复杂度,不是增加复杂度"。原 8 页签结构(总览/修复/同步/守护/AI/事件/历史/任务)等于把"打开哪个工具"换成了"点哪个 tab",认知成本没降。范围收窄到 **3 页签**(状态/变更/任务)+ 1 常驻侧栏(关键文档跳转),AI/事件/历史/同步 删除,守护/修复 并入状态页。详见 §4.1 修订表。

**会话隔离**:本任务的实现由独立对话推进(用户决策),与 `harness-governance-v1` 并行。

## 2. 触发原因(2026-04-24 GUI 实机验收反馈)

`control-panel-v1` V1.2 实机验收时用户反馈两条硬伤:

1. **左侧页面内容不能滚轮滚动**——只有页签可以
2. **右侧页面也滚不动**

**根因**:Tkinter 的 Frame 不带滚动,要做必须套 `Canvas + Scrollbar + 内嵌 Frame` 三层 + 手动 `<MouseWheel>` 事件绑定到每个子 widget。当前 v1 只在左侧页签做了部分套娃,内容区和右侧没做。这是 Tkinter 的 30 年设计遗留,补 Canvas 套娃能修但代码丑、维护贵、根本观感不变。

用户原话:"观感和交互有点差"。

**触发 §1.6 演进路径**:DESIGN(harness-governance-v1) §1.6 演进路径预留了"PySide / Web UI 当 Tkinter 渲染瓶颈时升级",触发条件已满足。

## 3. 选定方案(PySide6,理由汇总)

详细 5 选项对比已记录在本会话讨论(harness-governance-v1 一轮 chat),核心结论:

| 维度 | Tkinter(v1) | **PySide6(v2 选定)** | CustomTkinter | Web UI(FastAPI+前端) |
|---|---|---|---|---|
| 滚动 | ❌ 套娃 + 手绑 | ✅ `QScrollArea` 内建 | ❌ 内核同 Tkinter | ✅ 浏览器内建 |
| 观感 | 🟡 简陋 | 🟢 工业原生 | 🟡 主题化 | 🟢 最美 |
| 体积 | 0(stdlib) | ~50MB | ~5MB | 0(浏览器) |
| 与 v1 model 兼容 | — | ✅ view 层重写,model 不动 | ✅ | ❌ 双 stack |
| 边界违反 | — | 无 | 无 | ❌ 违反 v1 设计 §3 / 需求 §3 / SPEC §4 自定的"不开 HTTP" |

**选定 PySide6**,核心理由:
- 解决根问题(滚动内建)
- model 层(`control_panel_model.py`)已 MVC 解耦,迁移成本只在 view 层
- 桌面原生外观符合"主控面板"产品定位
- Python 同 stack,不引入跨语言

**否决 Web UI**:违反 control-panel-v1 自定的"不开 HTTP/WebSocket"边界(原文位于 v1 需求 §3 行 45-46 + v1 设计 §3 行 146 + v1 SPEC §4 行 48),且引入 server 进程会让"本地桌面工具"产品定位漂移。如果未来真要 Web,应单独立项不在本任务范围。

## 4. 范围

### 4.1 本期纳入(v2.1 收窄,2026-04-24)

**最终结构:3 tab + 1 侧栏 + 1 折叠区。**

| 范围 | 内容 |
|---|---|
| view 层 | `control_panel_pyside/`(包),实现 **3 页签**:状态 / 变更 / 任务,**不含**右侧结论面板(v2.0 的 ConclusionPanel 删除——简介合并到任务卡片点击行为) |
| **状态页**(默认视图) | 合并 v1/v2.0 的"总览 + 守护 + 修复"三页内容:Git 状态卡片 + Daemon 进程卡片 + 最近自动修复结果卡片 + **[一键修复] 按钮**(等价跑 `maintain.py --fix`) |
| **变更页**(新增) | 读 `~/.claude/global-memory/CHANGELOG.md` 倒序展示最近 N 条(默认 20),每条可点开看完整段落;底部 **[打开完整 CHANGELOG]** 按钮(用默认编辑器打开)。本页不轮询,切到本页或点刷新时拉一次 |
| **任务页**(保留 v2.0 设计) | 展示 active + archived 任务清单 + 简介 + stage 标识,数据源:`harness_status.py --tasks --json`。点卡片:①弹出该任务目录(系统文件管理器)②不再触发右侧面板(已删) |
| **关键文档侧栏**(常驻) | 右侧固定窄栏,列 4-6 个关键文件链接(MEMORY.md / CHANGELOG.md / conventions.md / 当前任务的 SPEC.md / HANDOFF.md),点击=用系统默认编辑器打开。文件清单写死在配置,不动态扫描 |
| **调试输出区** | 默认折叠(收起到底部一行 `▸ 调试输出`)。手动展开可见 CLI 原始输出 + JSON;诊断时才需要 |
| 第三方依赖 | `PySide6`(GUI)+ `pyqtdarktheme-fork`(主题,见 HANDOFF §7)+ `qtawesome`(字体图标);白名单见 §4.2 |
| 依赖声明 | `requirements.txt` 列出所有第三方;`.bat` 启动时 `pip install -r requirements.txt --quiet` 兜底自动装 |
| 启动入口(开发期) | `control_panel_pyside.bat`,直接 `python -m control_panel_pyside` |
| 一键打包 | `PyInstaller` 打包成 `control_panel_pyside.exe`,单文件,双击启动 |
| 测试 | 实机交互测试(不写 GUI 自动化测试,工作量过大) |

**v2.0 → v2.1 删除清单**:
- ❌ AI 页(用户:"没看明白有啥用")
- ❌ 事件 页(同上)
- ❌ 历史 页(用户日常不需要,需要时直接看 events.jsonl 原文)
- ❌ 同步 页(用户:"不用留",日常无 push 决策需求)
- ❌ 总览 / 守护 / 修复 三个独立页(并入状态页)
- ❌ 右侧 ConclusionPanel(简化掉,简介通过点任务卡片用文件管理器打开任务目录替代)
- ❌ 接账本(原依赖 harness-governance-v1 Phase 4-B 的 outcomes/recent_events,本期完全不做)
- ❌ 面板内"部署"按钮(改独立 `bootstrap.bat`,见 §4.2)

### 4.2 暂不纳入

- 不删 v1 Tkinter(留兼容期,用户实测 v2 稳定后再删)
- 不开 HTTP API(沿用 v1 的 JSONL 文件总线)
- 不做 GUI 自动化测试(pytest-qt 等成本不匹配)
- 不做 v1 → v2 自动迁移工具(用户手动启动 .bat 即可)
- **不在面板内放"新电脑部署"按钮**(2026-04-24 v2.1):部署一台电脑只做一次,常驻 UI 浪费空间。改为独立的 `harness/bootstrap.bat`(可单独立项,本任务不实现),用户新机从终端跑一次完事。面板专注"日常运行中"的需求

> **2026-04-24 边界调整**:原"不引入额外第三方"放宽。理由——个人项目自用,无合规/团队审查成本;PySide6 都装了,再装主题/图标库的边际成本接近 0;QSS 手写要做出现代感工作量比写应用本身还大,不值。允许范围:成熟、活跃维护、轻量(单库 ≤ 5 MB)的 PySide6 生态库。当前白名单:`PyQtDarkTheme`(主题)、`qtawesome`(字体图标)、`PyInstaller`(打包)。新增依赖需先在本节加白名单。
>
> **2026-04-24 打包决策调整**:原"不做打包成 .exe"放宽为"用 PyInstaller 一键打包 .exe"。理由——个人自用工具,启动便利性 > 体积。PySide6 + PyInstaller 产物 ~80-150 MB 可接受。

## 6. 风险与缓解

| 风险 | 现方案的代价 | 缓解 |
|---|---|---|
| PySide6 首次 pip install 拉 ~50MB,慢 | 装一次,不再触发 | 文档说明 + `pip install PySide6` 一行 |
| Qt 信号槽学习曲线 | 第一次写慢 | 用最简的 lambda 槽 + 纯代码 widget 树(不用 Qt Designer) |
| 跨平台文件路径(Windows / WSL) | view 层用 Path,无平台耦合 | 已有 `_lib.is_windows()` 工具(Phase 4-A 加) |
| v1 / v2 并存期用户混淆 | 可能误启 v1 | 在 v1 启动时显示"V2 已可用"提示;或文档明示 |
| 字体图标依赖 qtawesome | 增加 ~1 MB 依赖 | 已纳入 §4.2 白名单,体积可接受 |
| 商业 LGPL 协议 | 个人项目无影响 | 文档标注 |
| **PyInstaller 打包后体积膨胀**(~80-150 MB) | .exe 文件大,U 盘拷贝慢 | 个人自用可接受;若要瘦身后续再上 `--onefile --strip` 或 Nuitka |
| **PyQtDarkTheme / qtawesome 与 PySide6 主版本兼容** | 升 PySide6 7.x 时第三方可能滞后 | 不主动升 PySide6 大版本,固定 6.x;升级时先在 dev 环境验证 |

## 7. 不做的事

- 不开 HTTP API
- 不引入跨语言(Tauri / Electron)
- 不做 GUI 自动化测试
- 不动 model 层 / panel_api 业务逻辑
- 不引入超出 §4.2 白名单的第三方(任何新增需先回 §4.2 加白名单)
- **不在面板内做"新电脑部署"功能**(独立 bootstrap.bat,见 §4.2)
- **不接 harness-governance-v1 Phase 4-B 的账本 reader**(账本/事件/历史功能整体下线)
- **不维护任务对照"长版简介"渲染**(右侧 ConclusionPanel 删除,任务卡片点击=直接打开任务目录,简介在文件里看)
