## 1. 架构总览

本期设计不动现有 Claude Code 链路，只在外侧加一层“运行时兼容说明 + 上下文导出”。

```
global-memory
   │
   ├─ Core（通用）
   │    ├─ harness/maintain.py        doctor/status/fix/sync/report
   │    ├─ check_health.py            记忆仓库健康检查
   │    ├─ harness/verify_*.py        文档 / prompt / workflow 校验
   │    ├─ harness/control_panel.py   人类 GUI
   │    └─ harness/panel_api.py       本地 JSONL 事件入口
   │
   ├─ Runtime Adapter
   │    ├─ claude_code                ~/.claude/settings hooks + skills + agents
   │    ├─ codex_cli                  AGENTS/skills 风格上下文（后续）
   │    ├─ generic_cli                生成 prompt/context 包
   │    └─ api_provider               生成模型输入和边界说明
   │
   └─ Context Export
        ├─ 体系摘要
        ├─ 当前 Git/doctor/status
        ├─ 相关记忆入口
        ├─ 操作边界
        └─ 推荐命令
```

关键点：**Core 不知道自己被哪个 AI 调用**。Runtime Adapter 只负责把 Core 的能力翻译成目标环境能读懂的入口。

## 2. 能力矩阵

| 能力 | Claude Code | Codex/其他 CLI | Cursor/Continue/API | 无 AI |
|---|---|---|---|---|
| 读 README/MAINTENANCE | ✅ | ✅ | ✅ | ✅ |
| 跑 `maintain.py status/doctor` | ✅ | ✅ | ✅ 通过人工或脚本 | ✅ |
| GUI 主控台 | ✅ | ✅ | ✅ 本机可开 | ✅ |
| Stop 后自动同步 | ✅ 硬集成 | ❌ | ❌ | ❌ |
| PreToolUse 危险命令拦截 | ✅ 硬拦截 | ⚠️ 取决于工具 | ❌ 只能 prompt | ❌ |
| Skill 自动触发 | ✅ | ⚠️ 取决于工具 | ❌ | ❌ |
| 上下文导出 | 🚧 待做 | 🚧 待做 | 🚧 待做 | ✅ 可读 |
| 面板外部事件 | ✅ | ✅ | ✅ 只要能跑 CLI | ✅ |

状态解释：

- ✅：本期可以承诺。
- ⚠️：能力存在，但不是 harness 可硬保证。
- ❌：不要承诺。
- 🚧：后续实现项。

## 3. Context Export 接口

后续实现建议放在 `harness/export_context.py`，再由 `maintain.py export-context` 包一层。先独立脚本更容易测试，稳定后再收进主控 CLI。

命令草案：

```powershell
python harness\export_context.py --target generic --task "分析当前维护体系"
python harness\export_context.py --target codex --include-doctor
python harness\maintain.py export-context --target api --task-file prompt.txt --json
```

输出模式：

| 参数 | 输出 |
|---|---|
| `--target generic` | 一份 Markdown，上方是给 AI 的启动说明，下方是仓库状态和推荐命令。 |
| `--target codex` | 更偏 coding agent：强调不要破坏 dirty worktree、优先 `maintain.py`、改动后跑验证。 |
| `--target api` | JSON：`system_context`、`repo_status`、`allowed_actions`、`forbidden_actions`。 |
| `--include-doctor` | 内嵌 `maintain.py doctor --json` 摘要。 |
| `--include-diff` | 内嵌 `git diff --stat`，默认不放完整 diff，避免 prompt 过长。 |

Markdown 输出骨架：

```text
# global-memory Runtime Context

你正在协助维护 global-memory harness。

## 当前运行时
- target: generic
- Claude Code hooks: unavailable
- hard safety hooks: unavailable

## 操作边界
- 先读 README/MAINTENANCE/CONTROL_PANEL
- 只读检查用 maintain.py status/doctor
- 修改后跑 smoke/check_health
- 不要假设 Stop hook 会自动同步

## 当前状态
...

## 推荐下一步
...
```

## 4. Runtime Adapter 数据结构

先用 JSON manifest，不上类框架。

建议新增或扩展 `harness/maintenance_manifest.json`：

```json
{
  "runtime_capabilities": {
    "core": {
      "maintain_status": {"portable": true, "side_effect": "none"},
      "maintain_sync": {"portable": true, "side_effect": "commit_push"},
      "panel_api_notify": {"portable": true, "side_effect": "writes_user_log"}
    },
    "claude_code": {
      "settings_hooks": {"portable": false, "side_effect": "writes_claude_settings"},
      "stop_hook_sync": {"portable": false, "side_effect": "commit_push"}
    },
    "generic": {
      "context_export": {"portable": true, "side_effect": "stdout_only"}
    }
  }
}
```

这份 manifest 后续可以被 GUI 和维护报告读取，用来告诉人类：这个按钮/能力在哪些运行时可用。

## 5. 非 Claude Code 启动流程

给外部 AI 的最小启动协议：

```
1. 读取导出的 Runtime Context
2. 只读确认状态
   └─ python harness\maintain.py status --json
3. 如需深入诊断
   └─ python harness\maintain.py doctor --json
4. 提出计划，不假设 hooks 会兜底
5. 如需通知 GUI
   └─ python harness\panel_api.py notify ...
6. 修改后由人类或主控 CLI 跑验证和同步
```

非 Claude Code 下要反复提醒两件事：

- 没有 PreToolUse 硬拦截，危险操作必须靠 agent 自律和人类 review。
- 没有 Stop hook，任务结束后必须显式跑同步预览或让人类点 GUI。

## 6. 错误处理

| 场景 | 行为 |
|---|---|
| 当前不是 Git 仓库 | 导出上下文仍生成，但 `repo_status` 标注 unavailable。 |
| `maintain.py doctor` 超时 | 只写 status 摘要，doctor 标注 timeout。 |
| Claude Code runtime 不存在 | generic 导出不失败，只标注 hooks unavailable。 |
| GUI 没打开 | `panel_api.py notify` 仍写 JSONL，下次 GUI 打开可读。 |
| 外部 AI 无法跑命令 | Markdown 上下文仍可复制使用。 |

## 7. 测试策略

| 测试 | 标准 |
|---|---|
| `python -B harness\maintain.py status --json` | 只读，不改变 `git status --short`。 |
| `python -B harness\maintain.py doctor --json` | 不写 tracked 文件。 |
| `python -B harness\smoke_test.py --json` | 维护脚本仍全绿。 |
| `python -B check_health.py --json` | 记忆仓库无 error/warning。 |
| 后续 `export_context.py --target generic` | stdout 可读，不写文件。 |
| 后续 `export_context.py --target api --json` | JSON 可解析。 |

## 8. 迁移与回滚

迁移不需要改现有 runtime。Phase 1 只新增文档和导出脚本；Phase 2 再把 README/MAINTENANCE 指过去。

回滚很简单：

- 删除 `export_context.py` 和 manifest 的 `runtime_capabilities` 字段。
- 保留 Claude Code 的 `bootstrap.py`、hooks、skills、agents 原样。
- GUI 不依赖 Runtime Adapter 时不受影响。
