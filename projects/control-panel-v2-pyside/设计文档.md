### 3.1 通道清单与轮询策略

| 通道 | 写入端 | 读取频率 | 执行线程 | 备注 |
|---|---|---|---|---|
| `~/.claude/logs/control_panel_events.jsonl` | `panel_api.py notify`(裸 append,**无锁**) | 2s | 主线程 | 增量读 `last_offset`,需半行容错(见 §3.2) |
| `~/.claude/logs/task_outcomes.jsonl` | `panel_api.py outcome`(Phase 4-A,`_atomic_append_jsonl`,有原子性保障) | 2s | 主线程 | 等 4-B reader 就绪后联调;无半行风险 |
| `~/.claude/logs/tool_audit.jsonl` | hooks(audit_logger) | 5s | 主线程 | 写入频率低,2s 太密;增量读 |
| `D:/global-memory` git status | `subprocess.run(["git", "status", "--porcelain"])` | **10s + QThread 异步** | 工作线程 | Windows 下 git status 200-800ms,主线程会卡 UI;走 QThread + signal 回主线程 |
| 任务总览(harness-governance-v1 Phase 2-A.1 已交付) | `python harness/harness_status.py --tasks --json` | **按需 + 用户手动刷新** | 工作线程 | 切换到任务页时拉一次 + 顶部"刷新"按钮主动触发;不轮询(任务列表变化频率低);走 QThread |

**为什么不一刀切**:git status 是阻塞 subprocess(Windows 下首次 cold cache 可能 800ms),如果与 jsonl 同走 2s 主线程轮询,UI 每 2s 就会冻一下。jsonl 是纯文件读,毫秒级,2s 主线程 OK。

### 3.2 JSONL 鲁棒读取(应对 panel_api 裸 append 的半行风险)

**风险**:`panel_api.append_event()` 当前是 `f.write(json.dumps(...) + "\n")` 的裸调用,Windows 下可能在 v2 读取时正好读到半行,`json.loads` 抛 `JSONDecodeError`。

**polling.py 必须实现的容错**:

```python
def read_incremental(path: Path, last_offset: int) -> tuple[list[dict], int]:
    """读取 path 从 last_offset 起的新行,半行回退。"""
    new_events: list[dict] = []
    with open(path, "r", encoding="utf-8") as f:
        f.seek(last_offset)
        chunk = f.read()
        new_offset = last_offset

    # 按行切,最后一行如果不以 \n 结尾视为半行,丢弃
    lines = chunk.split("\n")
    if not chunk.endswith("\n"):
        lines = lines[:-1]   # 半行不要

    consumed = 0
    for line in lines:
        if not line.strip():
            consumed += len(line) + 1
            continue
        try:
            new_events.append(json.loads(line))
            consumed += len(line.encode("utf-8")) + 1
        except json.JSONDecodeError:
            # 单行损坏:跳过该行,继续后面;不回退 offset(避免死循环)
            consumed += len(line.encode("utf-8")) + 1
            continue

    return new_events, last_offset + consumed
```

**关键约束**:
- 半行(末尾无 `\n`)→ 不前进 offset,等下一轮重读
- 单行 `JSONDecodeError` → 跳过该行,offset 推进(避免死循环);记日志
- 文件被截断(rotate)→ 检测到 `file.size < last_offset` 时 reset 到 0 重读

### 3.3 轮询机制选择:QTimer,不上 QFileSystemWatcher

理由:2-10s 延迟对人类感知够用("过了 2 秒看到事件"和"立即看到事件"在控制面板场景里无差);加 QFileSystemWatcher 引入文件锁竞争 + 跨平台行为差异(Windows 监听文件改动有 buffer / WSL 通过 9P 协议会丢事件);未来若需实时,再切 watcher 不迟。

## 7. 详细设计

### 7.1 widget 树搭建方式 + 代码组织

**搭建方式:纯 Python 代码 widget 树**(不用 Qt Designer .ui 文件)

理由:
- 决策 3 按页签拆模块,每页是 `QWidget` 子类,纯代码在 `__init__` 里搭 layout 最自然
- 7 页签形态相似(标题 + QScrollArea + model 渲染区),可提取 `_BasePage` 基类复用,Designer 不好继承
- 与 v1 工作流一致(纯代码 / git diff 友好 / grep 可定位)
- Qt Designer 的拖拽收益要在"非程序员协作 / 50+ 字段密集表单 / 快速对比 5 种布局"才显现,本项目都不沾

**代码组织:按页签拆模块**

```
control_panel_pyside/
├── __init__.py
├── __main__.py            # 入口:QApplication + 主题 + 主窗口装配
├── main_window.py         # QMainWindow + QSplitter + QTabWidget 装配
├── theme.py               # PyQtDarkTheme 封装 + 主题持久化
├── polling.py             # QTimer 轮询 + JSONL 增量读取(last_offset)
├── views/
│   ├── __init__.py
│   ├── _base.py           # _BasePage(QWidget):标题栏 + QScrollArea 模板
│   ├── overview.py        # 总览页
│   ├── doctor.py          # 修复页
│   ├── sync.py            # 同步页
│   ├── guard.py           # 守护页
│   ├── ai.py              # AI 页
│   ├── events.py          # 事件页
│   ├── history.py         # 历史页
│   └── tasks.py           # 任务总览页(v2 新增,见 §7.7)
├── cli_invoke.py          # subprocess 封装 + QThread 异步,用于 git status / harness_status.py
└── conclusion_panel.py    # 右侧结论面板(QStackedWidget)
```

**约束**:
- 每个 `views/*.py` 不超过 300 行;超出说明该页职责过重,拆子组件
- 业务判断只在 model 层(已有 `harness/control_panel_model.py`),views 只做"调 model → 渲染 dict"
- `_base.py` 的 `_BasePage` 提供:标题栏 widget + 内嵌 QScrollArea + 一个 `refresh()` 抽象方法,7 个子类只实现 `_build_content()` 和 `refresh()`

### 7.2 信号槽连接风格

**混合策略**:同文件内用 lambda,跨文件 / 跨类用 `@Slot()` 装饰器。

**lambda(同文件简单连接)**:

```python
btn.clicked.connect(lambda: self._refresh())
combo.currentTextChanged.connect(lambda v: self._on_theme_changed(v))
```

**@Slot()(跨文件 / 需调试栈 / 需类型检查)**:

```python
from PySide6.QtCore import Slot

class OverviewPage(_BasePage):
    @Slot(dict)
    def on_polling_event(self, event: dict) -> None:
        # 跨文件信号(polling.py 发的)用显式 slot
        # 好处:堆栈里看得到方法名,IDE 能跳转
        ...

# polling.py
self.event_received.connect(overview_page.on_polling_event)
```

**详细信号清单**(Phase 2 开工时填):
- `polling.PollingService.event_received(dict)` → `views/*.refresh(event)`
- `theme.ThemeManager.theme_changed(str)` → `MainWindow._apply_theme()`
- `theme.ThemeManager.theme_changed(str)` → `MainWindow._refresh_all_icons()`(qtawesome icon 主题切换不自动重绘,需主动重建,见 §7.4)
- `MainWindow.tab_changed(int)` → `ConclusionPanel.switch_to(idx)`

**为什么是 Qt Signal(不是 Python callback)**:跨文件传 dict(polling → views 跨潜在线程边界),Qt Signal 自带 queued connection 跨线程安全;Python callback 要自己处理线程切换(`QMetaObject.invokeMethod` 或 `QTimer.singleShot(0, ...)`)更易出错。

### 7.3 主题方案(PyQtDarkTheme + 局部 QSS)

**主体策略**:`PyQtDarkTheme` 兜底现代外观,无需 QSS 手写工作。局部需要的微调(卡片圆角、状态色块)叠 QSS 覆盖。

**API 用法**(一行切主题):

```python
import qdarktheme

# main.py 启动时
app = QApplication(sys.argv)
qdarktheme.setup_theme("auto")   # auto / dark / light;auto 跟随系统
# 用户运行时切换:
qdarktheme.setup_theme("dark")   # 重新调用即可
```

**深/浅切换 UI 入口**:右上角菜单 `View → Theme → Auto/Dark/Light`,选项写入 `~/.claude/control_panel_pyside.json` 持久化,启动时读回。

**局部 QSS 微调点**(Phase 4 开工时确认):

- 状态卡片(总览页绿/黄/红条):用 QSS 设 `border-left: 4px solid <color>`
- 事件列表行高:`QListWidget::item { padding: 6px; }`
- 结论面板代码块:`QTextEdit { font-family: "JetBrains Mono"; }`

**不做**:不写整套 QSS 主题文件(那是 PyQtDarkTheme 的活);不引入 `qt-material` / `qdarkstyle` 等同类竞品。

### 7.4 图标方案(qtawesome)

**字体图标库**(免去维护 .png 资源):

```python
import qtawesome as qta

# 用法
btn = QPushButton(qta.icon("fa5s.sync"), "同步")
tab.addTab(page, qta.icon("fa5s.heartbeat"), "守护")
```

**图标取色**:`qtawesome` 创建 icon 时锁定颜色(取自当时的 palette)——**不会随主题切换自动反色**。运行时切主题(V7 要求)需主动重建已挂载的 icon。

**主题切换时的 icon refresh 流程**:

```python
class MainWindow(QMainWindow):
    def __init__(self):
        ...
        self._tab_icons: dict[int, str] = {0: "fa5s.tachometer-alt", 1: "fa5s.tools", ...}
        theme_mgr.theme_changed.connect(self._refresh_all_icons)

    @Slot(str)
    def _refresh_all_icons(self, theme: str) -> None:
        # 重建所有 tab icon(qtawesome 会取当前 palette 的新色)
        for idx, icon_name in self._tab_icons.items():
            self.tabs.setTabIcon(idx, qta.icon(icon_name))
        # views/* 内部如有 icon,也通过 signal 通知各自重建
```

**图标集选用**:Font Awesome 5 (`fa5s.*` 实心 / `fa5r.*` 线性),覆盖度足够 7 页签所需。

### 7.5 启动性能(按形态分预算)

| 形态 | 冷启预算 | 构成 |
|---|---|---|
| **`.bat` 直跑(开发期)** | < 1.5s | PySide6 import ~400-700ms + PyQtDarkTheme setup ~50ms + 业务初始化 ~500ms |
| **`.exe`(PyInstaller `--onefile`)** | < 5s | 上述 + onefile 解包临时目录 ~1-2s + 首次 Win Defender 扫描 ~1s |
| **`.exe`(PyInstaller 目录形态,非 onefile)** | < 2s | 上述基础不解包,接近 .bat |

**结论**:开发期(.bat)用 1.5s 预算;发布期(.exe `--onefile`)预算放宽到 5s,与 §8.2 配置一致。如要 .exe 也接近 1.5s,可改 PyInstaller 目录形态(放弃单文件分发便利换启动速度)。Phase 4 实测后定。

**TaskCard 结构**:

  └─ QVBoxLayout

**信号清单**(补充到 §7.2):
- `TaskCard.clicked(str)` (任务名) → `MainWindow._on_task_card_clicked()`
- `MainWindow._on_task_card_clicked()` 双动作:
  - `subprocess.Popen(["explorer", task_path])`(Windows)/`xdg-open`(Linux)打开任务目录
  - `conclusion_panel.show_task_brief(name)` 在右侧渲染长版简介(读取 `需求分析.md` / `HANDOFF.md` 完整 §1)

**刷新策略**:
- 切换到任务页时自动拉一次(在 `tasks_page.showEvent()`)
- 用户手动点"刷新"按钮触发
- **不轮询**——任务列表变化频率低(创建 / 归档都是人为动作),轮询无意义

**异步执行**(避免主线程卡):
- `cli_invoke.run_async([...harness_status.py, --tasks, --json], on_done=callback)` 走 QThread
- 加载中卡片区显示 spinner(`qta.icon("fa5s.spinner", animation=qta.Spin(...))`),数据回来后替换

**错误处理**:
- CLI 返回非 0 → 顶部红条 banner "harness_status.py --tasks 执行失败,见日志"
- JSON 解析失败 → 同上
- 不抛 exception 到 UI 线程

**Phase 归属**:此页归到 Phase 2(7 页签内容)同期实现——CLI 已就绪,v2 这边只是渲染层,不依赖任何待交付物。

**spec 配置策略**:

```python
# control_panel_pyside.spec(Phase 5 开工时落地)
a = Analysis(
    ['control_panel_pyside/__main__.py'],
    hiddenimports=['qdarktheme', 'qtawesome'],  # 避免动态 import 漏打包
    excludes=['tkinter', 'unittest', 'test'],   # 减体积
    ...
)
exe = EXE(..., name='control_panel_pyside', console=False)
```

**关键参数**:

- `--onefile`:打成单 .exe,**启动 3-5s**(解包到临时目录 + PySide6 import + Win Defender 扫描),便于分发(单文件可拷贝)
- `--windowed`:不弹 console
- 不签名(个人自用,Win Defender 第一次会提示,可手动放行)

**启动速度 vs 分发便利的取舍**:
- onefile(默认选用):**3-5s 冷启**,U 盘 / 邮件附件友好
- 目录形态(`pyinstaller spec` 不加 `--onefile`):**< 2s 冷启**,产物是文件夹(几百个文件),分发要打包成 zip
- Phase 5 实测后按个人使用偏好选;若 .exe 启动慢到难忍,切目录形态

**预期体积**:80-150 MB(PySide6 占大头)。瘦身路径(后续可选):`--strip` / 改 Nuitka / 用 PySide6-Essentials 子集。Nuitka 对 PySide6 体积优势可观(30-50%),但本期优先生态成熟度,推迟到 Phase 5+。

**构建命令**:

```bat
pyinstaller control_panel_pyside.spec
:: 产物在 dist/control_panel_pyside.exe
```

**与开发期 .bat 共存**:开发改代码用 `.bat` 直跑;发布版本时跑一次 `pyinstaller` 出 .exe。
