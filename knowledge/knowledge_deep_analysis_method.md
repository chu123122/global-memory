# 深度分析方法论：4 个可迁移内核

> 提炼自 hv-analysis（横纵分析法）与 khazix-writer 两个 skill，剥掉公众号文风、PDF 排版、选题套路等场景皮，只留去语境的思维内核。
> 用法是「透镜」不是「流程」——遇到对应场景就调出这组提问，不必整套走完，也不限于「写研究报告」这一个出口。

## 内核① 双轴交叉分析法（研究 / 调研 / 复盘任何对象）

- **纵轴 = 时间深度**：起源（为什么是这群人在这个时点做）→ 演进关键节点 → **决策逻辑还原（为什么选 A 不选 B、当时的约束是什么）** → 阶段划分 → 锁定效应（什么机制让它越走越深、难以逆转）。
- **横轴 = 同期广度**：先判断参照系场景（无同类 / 1-2 个 / 3+）→ 多维对比（路线 / 形态 / 受众 / 优劣 / 体量）→ **真实口碑而非官方口径** → 生态位（填了什么空白、在跟谁正面竞争）。
- **交叉 = 产出新判断（不是两轴的缩写）**：历史决策如何锁定了今天的位置；今天每个优劣能追溯到哪个历史节点（当年的「好决策」有没有变成今天的包袱）；三剧本推演（最可能 / 最危险 / 最乐观，每个都要逻辑支撑）。
- **去语境读法**：把「竞品」读成「同类参照系」、「版本迭代」读成「关键节点」，于是它能研究技术选型、一个团队、一个决策、一段事故的来龙去脉，不只是产品/公司。

## 内核② 信息收集协议

- 按**信息类型**拆并行（纵向史料组 / 横向对比组 / 补充组），不按步骤拆。
- 给执行者的指令**写目标不写手段**（用「调研 / 了解」而非「搜索 / 爬取」），让它自选最佳获取路径。
- 一手 > 二手；警惕「多源引用同一错误 = 循环印证假象」。
- 收尾自检：能讲出一个完整故事吗？有没有信息断层？参照系全不全？有没有只靠单一来源就下判断？
- 搜不到就诚实标「暂缺」，绝不编造（呼应铁律 #10 fail-loud）。

## 内核③ 分层质检金字塔（任何交付物的审查元模板）

- 先自动后人工、先客观后主观，四层递进：
  - **L1 硬规则**：机器可扫的禁令 / 格式 / 硬约束（语法层）。
  - **L2 模式匹配**：是否符合既定风格 / 结构（单元测试层）。
  - **L3 内容深度**：观点有无具体支撑、有无空泛论断（集成测试层）。
  - **L4 终审**：最主观的「目标 / 人格」通读——这达成初衷了吗、像不像该有的样子。
- 通用化：套到代码审查、文档、报告皆可。harness 里的 verify / guardian / code-review 是它的实例，这层金字塔是它们共享的元模板。

## 内核④ 剥开式推理（分析任何事物的提问透镜）

- 「现象 → 表面解释 → 更深追问 → 核心洞察」，不直接抛结论，带自己和读者走一遍推理。
- 永远多问一层：不只问「发生了什么」，而问「为什么这么选」；当年的好决策有没有变成今天的负债。

## 常见误区

- 把双轴写成两段并列描述，省掉「交叉」——价值全在交叉那一步的新判断。
- 纵轴写成年表流水账（只有「何时发生了什么」），丢了决策逻辑还原。
- 横向对比写成参数对照表，没讲清每个对象「活成了什么样」、用户选它的真实理由。
- 质检层次打乱（先做主观判断再补硬规则），导致返工。
