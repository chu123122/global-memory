# Design · control-panel-v1

> 文档类型：设计文档
> 创建：2026-04-24
> 配套需求分析：`REQUIREMENTS.md`
> Status: implementation

## 1. 架构总览

```text
人类
  │
  ▼
harness/control_panel.py  Tkinter 中文 GUI
  │
  ├─ maintain.py status/doctor/fix/sync/daemon/log/report
  │
  ├─ control_panel_model.py 提炼结论/下一步/关键数据
  │
  ├─ ai_runner.py diagnose/plan
  │
  └─ panel_api.py 写入的 control_panel_events.jsonl
```

原则：

- GUI 是薄外壳，不直接复制底层脚本逻辑。
- `maintain.py` 是维护动作唯一主控入口。
- 只读接口和有副作用接口分开。
- 外部 AI 不直接控制 GUI，而是写事件给 GUI 轮询显示。
- 默认界面必须降低理解门槛：用户先看到“结论”和“下一步”，而不是命令、JSON、脚本名。
- 原始命令行是调试层，不是主界面；只有出错或开发面板时才打开。

## 1.1 产品原则

面板不是“把 CLI 搬进窗口”，而是一个傻瓜式维护入口。用户打开后应该先得到一句可执行结论：

```
有 18 个改动，先别急着同步
下一步：去“同步”页点“生成同步预览”
原因：当前分组 harness 13 / docs 3 / memory 2；最近自动同步失败，push 前先确认。
```

主界面优先级：

| 优先级 | 内容 | 说明 |
|---|---|---|
| P0 | 当前结论 | 用一句话告诉用户现在是否正常、有没有风险。 |
| P0 | 下一步按钮/动作 | 明确“点哪里”，不要让用户读完一堆脚本名后自己判断。 |
| P1 | 关键数据 | Git dirty/ahead/behind、daemon、doctor、同步预览、事件。 |
| P2 | 明细表 | 变更文件、事件列表、检查项列表。 |
| P3 | 原始命令输出 | 默认隐藏，仅调试时展开。 |

## 2. 关键组件

| 组件 | 职责 |
|---|---|
| `maintain.py` | 主控 CLI，提供状态、体检、修复、同步、daemon、历史、报告。 |
| `control_panel.py` | Tkinter 面板，负责中文 UI、按钮、自动刷新、事件显示。 |
| `control_panel_model.py` | 纯数据提炼层，把 JSON 转成人类结论、下一步动作、卡片数据。 |
| `test_control_panel_model.py` | 模型层单元测试，不启动 GUI。 |
| `ai_runner.py` | Claude CLI adapter；V1 只允许 diagnose/plan。 |
| `panel_api.py` | 本地事件 API，把 AI/脚本通知写入 JSONL。 |
| `control_panel_events.jsonl` | 面板事件总线，位于 `~/.claude/logs/`。 |

## 3. 数据流

### 3.0 数据提炼层

所有 CLI 返回的 JSON 先进入 `control_panel_model.py`，再进入 Tkinter。UI 不直接判断“下一步该干什么”。

```text
maintain.py / ai_runner.py / panel_api.py
  │ JSON / event dict
  ▼
control_panel_model.py
  ├─ summarize_status()
  ├─ summarize_doctor()
  ├─ summarize_sync_preview()
  ├─ summarize_log()
  └─ summarize_event()
       │
       ├─ decision: {level, headline, next_action, why}
       ├─ cards: [{title, value, level}]
       ├─ tables: changes / checks / events
       └─ debug: raw output only when requested
```

数据提炼契约：

| 输入 | 输出给 GUI | 默认是否展示命令行 |
|---|---|---|
| `status --json` | 当前结论、Git/daemon/最近提交卡片、变更文件明细 | 否 |
| `doctor --json` | 体检结论、失败/警告检查项、下一步建议 | 否 |
| `sync --preview --json` | checkpoint 摘要、文件分组、变更明细、同步前确认提示 | 否 |
| `log --json` | semantic/checkpoint 比例、最近提交列表 | 否 |
| `panel_api notify` | 最新事件、事件表、必要时右侧结论提醒 | 否 |
| 非 JSON / 脚本失败 | 失败结论 + “打开调试输出”提示 | 是，可由用户展开 |

### 3.1 快速状态刷新

```text
control_panel.py
  every 10s
  └─ python maintain.py status --json
       └─ 返回 Git/daemon/recent_commits/logs
```

自动刷新使用 quiet 模式：

- 不写右侧输出区。
- 不把状态栏长期置为“正在运行”。
- 只更新总览、同步预览卡片和右侧结论面板。

### 3.2 同步预览

```text
用户点击“生成同步预览”
  └─ maintain.py sync --preview --source gui --json
       └─ parse git status
       └─ group_files()
       └─ build_checkpoint_payload()
```

要求：

- 不运行 safe fix。
- 不 `git add`。
- 不 commit。
- 不 push。

### 3.3 外部事件

```text
AI/脚本
  └─ python harness/panel_api.py notify --source ai --level info --title ... --message ...
       └─ append ~/.claude/logs/control_panel_events.jsonl

control_panel.py
  every 2s
  └─ read new JSONL lines
       └─ update “事件” tab
       └─ append right output panel
```

V1 使用文件型事件总线，不开放 HTTP 端口。

## 4. UI 结构

### 4.1 页签结构

| 页签 | 内容 |
|---|---|
| 总览 | 快速状态、Doctor 明细、常用入口。 |
| 修复 | 安全修复、Bootstrap 检查/重部署。 |
| 同步 | Git 状态、同步预览、checkpoint 推送。 |
| 守护 | daemon 状态、启动、停止、日志尾部。 |
| AI | provider/mode/permission、上下文选项、提示词。 |
| 事件 | 外部事件最新状态、调用示例、事件日志入口。 |
| 历史 | 最近提交、维护报告、JSONL 日志入口。 |

### 4.2 默认右侧区域

右侧不再叫“运行输出”，而是“现在该看什么”。

```text
┌────────────────────────────────────┐
│ 当前结论：有 18 个改动，先别急着同步 │
├────────────────────────────────────┤
│ 下一步：去“同步”页点“生成同步预览”   │
├────────────────────────────────────┤
│ 原因：harness 13 / docs 3 / memory 2 │
├────────────────────────────────────┤
│ 关键数据表                          │
│ Git / Daemon / 最近提交 / 变更分组   │
├────────────────────────────────────┤
│ □ 显示原始命令输出（调试用）          │
└────────────────────────────────────┘
```

默认状态下用户不需要看命令行。调试输出区只有三个用途：

- 脚本失败，结构化摘要不足以定位问题。
- 开发面板本身，需要确认调用了什么命令。
- 用户明确想看原始 JSON / stdout / stderr。

### 4.3 傻瓜式主流程

用户主路径只保留 3 个动作：

```text
打开面板
  │
  ▼
看右侧“当前结论”
  │
  ├─ 没变更 → 需要巡检就点“运行完整体检”
  ├─ 有变更 → 去“同步”页点“生成同步预览”
  ├─ 有错误 → 不同步，先看“体检”结果或调试输出
  └─ daemon 没开 → 想自动同步才去“守护”页启动
```

按钮命名避免“工程内部词”优先：

| 旧倾向 | 新倾向 |
|---|---|
| `doctor` | `运行完整体检` |
| `sync preview` | `生成同步预览` |
| `daemon status` | `查看自动同步状态` |
| `log` | `查看最近提交` |
| `raw output` | `调试输出` |

V1.1 增强：

- 同步页增加 `Treeview` 变更文件明细，直接显示 Git 状态码和文件路径。
- 事件页增加 `Treeview` 事件列表，展示时间、级别、来源、标题。
- 事件列表按 `info/success/warning/error` 着色，减少右侧输出区刷屏依赖。

V1.2 增强：

- 右侧默认是“现在该看什么”结论面板，而不是命令行输出。
- 原始命令和 JSON 输出默认隐藏，通过“显示原始命令输出（调试用）”开关打开。
- 状态、doctor、同步预览、提交日志、外部事件都先经过 `control_panel_model.py` 提炼。
- UI 只负责渲染，数据判断逻辑由可测试纯函数承担。

当前实现注意：

- `test_control_panel_model.py` 已可直接运行通过。
- `smoke_test.py` 的直接文件 import 方式暴露了 `control_panel_model.py` 导入兼容问题，下一步需要修复模型层或 smoke import 方式，确保“模型测试 + smoke 注册”同时通过。

左侧页签内容统一用 Canvas + Scrollbar 包裹。滚轮策略：

- 鼠标进入左侧滚动区域时绑定 `<MouseWheel>`、`<Button-4>`、`<Button-5>`。
- 鼠标离开时解绑。
- Windows/macOS 使用 `event.delta`，Linux 使用 Button-4/5。
- 右侧输出区不受左侧滚轮绑定影响。

## 5. 安全边界

| 操作 | 允许副作用 |
|---|---|
| `status` | 无 |
| `doctor` | 无 tracked 文件变化；有 guard 检查。 |
| `sync --preview` | 无 |
| `fix` | 可修改本地 tracked 文件，但不提交不推送。 |
| `sync` | 可 safe-fix、pull、add、commit、push。 |
| `daemon start/stop` | 启停进程。 |
| `panel_api notify` | 写 `~/.claude/logs/control_panel_events.jsonl`，不写仓库。 |
| `ai_runner --mode execute` | V1 拒绝。 |

## 6. 测试策略

### 6.1 自动测试

| 测试 | 期望 |
|---|---|
| import/compile | `control_panel.py`、`maintain.py`、`ai_runner.py`、`panel_api.py` 可导入。 |
| status readonly | `status --json` 前后 `git status --short` 不变。 |
| preview readonly | `sync --preview --json` 前后 `git status --short` 不变。 |
| event API | `panel_api.py notify --json` 返回写入记录。 |
| doctor | `maintain.py doctor --json` 通过。 |
| smoke | `smoke_test.py --json` 通过。 |
| memory health | `check_health.py --json` 无 error/warning。 |
| GUI manual | 打开面板后滚轮可滚，事件页可收到 notify。 |
| structured UI | 同步页能看到变更文件表，事件页能看到最近事件表。 |
| model unit | `python -B harness\test_control_panel_model.py` 全部通过。 |
| smoke registration | `smoke_test.py --json` 会运行模型测试并 import GUI/model。 |

### 6.2 模型层测试用例

`test_control_panel_model.py` 至少覆盖：

| 用例 | 输入 | 期望 |
|---|---|---|
| dirty status | `dirty=True, change_count>0` | 结论提示“先生成同步预览”。 |
| clean status | `dirty=False` | 结论提示可运行完整体检或继续观察。 |
| sync failed | 最近日志含 `pull --rebase failed` | warning 中直接提示自动同步失败。 |
| doctor warning | `summary.WARNING>0` | 体检结论是 warning，不误报 error。 |
| doctor error | `summary.ERROR>0` | 下一步提示不要同步，先看错误项。 |
| sync preview | `file_count>0` | 展示候选提交、分组和变更文件。 |
| log summary | semantic/checkpoint entries | 展示语义提交和 checkpoint 数。 |
| event summary | notify event | 生成去重 key、时间、level、source、title。 |

### 6.3 GUI 手动验收

自动测试不启动 Tkinter 主循环；GUI 仍需人工验收：

| 场景 | 操作 | 期望 |
|---|---|---|
| 默认界面 | 打开 `control_panel.bat` | 右侧先看到结论/下一步/关键数据，不是命令行。 |
| 调试输出 | 勾选“显示原始命令输出” | 原始命令区域出现；取消后隐藏。 |
| 滚轮 | 鼠标放左侧页签区域滚动 | 左侧内容滚动，右侧不被抢滚轮。 |
| 同步预览 | 点“生成同步预览” | 右侧结论更新，变更文件表出现。 |
| 外部事件 | 运行 `panel_api.py notify` | 事件表新增一行，warning/error 有颜色。 |
| 错误态 | 构造脚本失败或查看已有失败日志 | 右侧明确提示打开调试输出。 |

## 7. 后续可演进点

- 事件日志轮转。
- 更强的一键流程向导。
- 把“运行完整体检”的结果做成分组卡片，而不是只更新列表。
- 给每个高风险按钮补“影响范围摘要”确认框。
- 本地 HTTP API。
- PySide6 或 Web UI 迁移。
