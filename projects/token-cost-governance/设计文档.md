## 1. 架构原则

本任务只做一层"薄脚本 + Skill 入口接线",不新增常驻服务,不新增持久数据通道。

| 原则 | 约束 |
|---|---|
| 只读优先 | `work_context_pack.py`、`audit_skill.py`、`check_prepare.py` 默认不得写 tracked 文件 |
| registry 单源 | 任务根、active tasks、required docs、skill 路径优先从 registry / bootstrap 读取,禁止硬编码任务列表 |
| 短摘要优先 | 默认人类输出 ≤120 行;完整结构放 `--json`;调试细节放 `--verbose` |
| AI 保留语义层 | 脚本只收集/校验/压缩材料,不替代方案判断、设计审查、风险取舍 |
| 先小后大 | 首批 3 个脚本;review/bug/memory 三个场景等数据证明后再做 |

数据流:

```text
registry / MEMORY / task docs / skills
  -> pack/audit/prepare scripts
  -> short summary or JSON
  -> Skill entrypoint
  -> AI semantic decision
```

## 2. Phase 0:Read-only Purity

目标:让"检查"命令可重复执行且不污染工作区。否则后续脚本即使设计为只读,也无法可信验证。

检查对象:
- `python harness/maintain.py doctor`
- `python harness/maintain.py status`
- `python harness/harness_status.py --json` 或等价入口
- 即将新增的三个 token saver 脚本

处理规则:
- 默认不写 `STATUS_SNAPSHOT.md`;如需要落盘,必须显式 `--write-snapshot`。
- 避免 import 产生 `__pycache__` 被纳入 tracked diff;如已有 tracked pycache,单独清理。
- smoke/doctor 类命令不得自动修复、自动提交、自动重写 registry。

验收:
```powershell
git status --short
python harness/maintain.py doctor
python harness/maintain.py status
git status --short
```

前后 tracked diff 不应增加。

## 3. Phase 1:`audit_skill.py`

角色:Skill 结构审计器,替代 AI 对 YAML、行数、引用资源、部署链接的逐项人工扫描。

CLI:

```bash
python harness/audit_skill.py --skill work
python harness/audit_skill.py --skill ./skills/work/v1
python harness/audit_skill.py --all
python harness/audit_skill.py --all --json
```

输入来源:
- `bootstrap.SKILLS` 作为 canonical skill 集合。
- `<repo>/skills/*/v1/SKILL.md` 作为源码。
- `~/.claude/skills/*` 作为部署位/junction 检查对象。

检查项:

| 检查 | 失败级别 |
|---|---|
| `SKILL.md` 不存在 | ERROR |
| YAML `name` / `description` 缺失 | ERROR |
| description 没有触发条件 | WARNING |
| `SKILL.md` 超过 500 行 | WARNING |
| 引用的 `scripts/` / `references/` / `assets/` 不存在 | ERROR |
| deployed skill 不在 `bootstrap.SKILLS` | WARNING |
| junction 指向非当前 repo | ERROR |

输出 schema:

```json
{
  "schema_version": 1,
  "kind": "skill_audit",
  "level": "PASS",
  "skills": [],
  "issues": []
}
```

## 4. Phase 2:`work_context_pack.py`

角色:`/work` 的上下文压缩入口。脚本先完成任务定位、文档状态、上次进度和最小 Read 清单,AI 再判断下一步。

CLI:

```bash
python harness/work_context_pack.py
python harness/work_context_pack.py --task token-cost-governance
python harness/work_context_pack.py --cwd . --json
```

读取:
- registry 的 `active_tasks`、`task_paths`、`tasks_root`、`human_doc_patterns`。
- `MEMORY.md` 的活跃项目区块,只抽任务名和一句话状态。
- task docs:`需求分析.md`、`设计文档.md`、`SPEC.md`、`HANDOFF.md`。

默认输出:
- resolved task 或候选 tasks。
- 当前 stage/status。
- 缺失文档。
- 最近进度摘要。
- 推荐下一步。
- AI 需要 Read 的最小文件列表。

JSON schema:

```json
{
  "schema_version": 1,
  "kind": "work_context",
  "level": "PASS",
  "task": "token-cost-governance",
  "confidence": 0.9,
  "summary": "...",
  "required_reads": []
}
```

## 5. Phase 3:`check_prepare.py`

角色:`/check` 的 deterministic preflight。脚本只做材料准备,不做设计结论。

CLI:

```bash
python harness/check_prepare.py --task token-cost-governance
python harness/check_prepare.py --task ./projects/token-cost-governance --json
```

读取:
- registry 的 task 解析信息。
- 目标任务目录下的 `.md` 文件。
- `required_docs_by_stage` 或现有 equivalent 配置。

检查:
- 必需文档是否存在。
- `Status` 是否可解析。
- TODO / TBD / 占位符。
- 空章节。
- 过长文档提示。
- 是否已有 `REVIEW-*.md`,避免覆盖历史 review。

输出给 `/check`:
- resolved task dir。
- 推荐审查文档列表。
- 缺失项。
- 预检警告。
- 推荐给 design-reviewer 的 prompt input 清单。

## 6. Phase 4:Skill + Manifest 接入

Skill 接线:

| Skill | 接入点 | 新行为 |
|---|---|---|
| `/work` | Step 0/1 | 先运行 `work_context_pack.py`,AI 只读短摘要和必要文件 |
| `/check` | Step 1 | 先运行 `check_prepare.py --json`,AI 再派 design-reviewer |
| `skill-auditor` | 审计入口 | 先运行 `audit_skill.py`,AI 解释结果和修复建议 |

`maintenance_manifest.json` 增加:

```json
"token_savers": {
  "description": "Read-only context packing and mechanical audits to reduce AI token usage.",
  "scripts": [
    {"id": "work_context_pack", "path": "work_context_pack.py", "args": ["--json"], "category": "read_only"},
    {"id": "audit_skill", "path": "audit_skill.py", "args": ["--all", "--json"], "category": "read_only"},
    {"id": "check_prepare", "path": "check_prepare.py", "args": ["--json"], "category": "read_only"}
  ]
}
```

暂不新增 `maintain.py token` 聚合命令。先让 manifest 可发现,等使用频率稳定后再决定是否加统一入口。

## 7. Phase 5:后续 Pack 评估

候选脚本:

| 脚本 | 触发条件 |
|---|---|
| `review_preflight.py` | review 场景连续 3 次需要 AI 手工收集 diff/stat/TODO |
| `bug_pack.py` | bug 排查连续 3 次需要 AI 手工收集日志、构建错误、历史 fixes |
| `memory_add.py` | 记忆写入连续 3 次出现 frontmatter / CHANGELOG / MEMORY 索引同步返工 |

这些脚本不在首批实现。原因是它们要么输入差异更大,要么涉及写入,需要真实样本后再定 schema。

## 8. 风险控制

| 风险 | 控制点 |
|---|---|
| pack 脚本输出膨胀 | 默认输出行数限制;测试中检查 ≤120 行 |
| 硬编码路径回潮 | 用现有硬编码检查脚本审新增文件;路径从 registry/bootstrap 读 |
| 脚本误导 AI | 输出 `confidence`、`level`、`warnings`;低置信不自动决策 |
| 维护面扩大 | 首批 3 个脚本共享 `_lib.py` 的 registry/task 解析函数 |
| 与 harness-governance-v1 混淆 | 本任务只管 token 降耗;状态面板、账本、hook smoke 仍归 harness-governance-v1 |
