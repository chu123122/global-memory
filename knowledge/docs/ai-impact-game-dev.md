# AI 对游戏程序员的影响推演

> 生成日期：2026-04-13
> 用途：长期职业方向参考 + 面试可能被问到

---

## 一、被替代风险排序（高 → 低）

| 排名 | 方向 | 风险 | 原因 |
|:---:|------|:---:|------|
| 1 | **UI 开发** | 🔴 极高 | AI 工具能直接从设计稿生成 UI 代码，且正确性容易验证 |
| 2 | **业务逻辑（战斗数值/任务系统）** | 🔴 高 | 规则明确、输入输出清晰，AI 擅长的领域 |
| 3 | **工具开发** | 🟡 中高 | AI 能快速生成编辑器插件和 Pipeline 工具，但复杂工具链需要深度理解 |
| 4 | **网络同步** | 🟡 中 | 涉及分布式状态一致性，AI 能写代码但很难调试"万分之一概率的不同步" |
| 5 | **物理模拟** | 🟢 中低 | 数学密集 + 调参需要直觉，AI 不擅长"手感调优" |
| 6 | **渲染** | 🟢 低 | GPU 架构 + 数学 + 视觉审美三重门槛，AI 短期无法替代 shader 调优 |
| 7 | **引擎底层** | 🟢 极低 | 系统架构设计、跨平台兼容、性能极限优化，需要对硬件和 OS 的深刻理解 |

### 规律总结

- **越接近确定性逻辑、越容易验证正确性的工作** → AI 替代越快
- **越需要处理模糊约束、硬件直觉、性能极限的工作** → AI 替代越慢
- **跨层问题排查**（"某设备偶尔崩溃"）→ AI 完全无能为力

## 二、AI 时代真正值钱的具体能力

| 能力 | 为什么值钱 | 怎么培养 |
|------|----------|---------|
| **系统架构设计** | AI 能写 1000 行函数，但不能设计耦合合理的模块系统 | 每个项目画架构图，练"四步法"（拆模块→定数据→画交互→走流程） |
| **性能诊断** | AI 不会用 Profiler，不理解 Cache Miss 和 False Sharing | 用 Unity Profiler/UE Insights 实际分析自己的项目 |
| **跨层问题排查** | "某个设备上偶尔崩溃"这种问题 AI 完全无能为力 | 实习中多接 Bug，越诡异的越值得记录 |
| **技术方案评审** | 判断方案的 trade-off 需要经验和直觉 | 旁听技术评审，记录别人的思考方式 |
| **与 AI 协作的能力** | 会用 AI 的程序员 vs 不会用的，产出差距已是 3-5 倍 | 持续进化 AI 工作系统 |

### 不要说的空话 vs 具体的真话

| ❌ 空话 | ✅ 具体技能 |
|---------|-----------|
| "创造力" | 系统架构设计 — 具体到能画出模块依赖图 |
| "沟通能力" | 技术方案评审 — 具体到能指出方案的 3 个 trade-off |
| "学习能力" | AI 协作能力 — 具体到能用 Prompt 让 AI 写出 90 分代码然后自己改到 100 分 |

## 三、我的方向（引擎/物理/网络/ECS）在 AI 时代的前景

### 好消息：选的方向是 AI 最难替代的

物理模拟、网络同步、ECS 架构 — 这些都是**约束密集型**问题：
- 必须保证确定性（帧同步）
- 必须满足严格性能预算（16ms 帧时间）
- 错误表现为"偶尔卡一下"或"千分之一概率不同步"，AI 极难定位

### 需要调整的

1. **补渲染基础**：不需要精通，但"能读懂 shader、能和渲染程序员对话"是引擎开发者必备
2. **学会用 AI 加速工作**：AI 工作系统（双 Agent + 知识库）已走在前面，保持这个优势
3. **80% UE + 20% 引擎无关能力**：UE 是吃饭工具必须精通，但真正值钱的是通用能力

### 通用能力 > 具体引擎

| 通用能力 | UE 的实现 | 为什么是通用的 |
|---------|----------|--------------|
| 资源管理架构 | FStreamableManager | 任何引擎都需要异步加载 + 引用计数 |
| 多线程调度模式 | TaskGraph | 思想通用，只是 API 不同 |
| 网络同步算法 | NetDriver | GGPO/帧同步与引擎无关 |
| ECS 设计 | 无原生支持 | 你在 Unity DOTS 上的经验可迁移到任何 ECS 框架 |

## 四、独立游戏开发的门槛变化

### AI 降低了什么门槛

| 环节 | 2024 年前 | 2026 年 |
|------|----------|---------|
| **美术** | 必须外包或自学数月 | AI 生成 → 人工微调，1-2 人可产出中等质量美术 |
| **关卡设计** | 纯手工，耗时巨大 | AI 辅助生成 + 人工调整，效率提升 5-10 倍 |
| **音乐/音效** | 需要专业能力 | AI 生成基本可用的音乐和音效 |
| **程序** | 仍需扎实基础 | AI 能写业务逻辑/UI，但引擎层仍需人类 |
| **设计** | 无变化 | 游戏设计的"乐趣"部分 AI 目前不能替代 |

### 一个人能做到什么程度

- **2024 年前**：一个人能做 Undertale 级别（像素+简单战斗）
- **2026 年**：一个擅长引擎技术 + 会用 AI 做美术的人，能做 Hollow Knight 级别的视觉品质 + Celeste 级别的手感
- **关键瓶颈**：不是技术，是设计。AI 能帮你做资产，但不能帮你设计"什么是好玩的"

### 对职业规划的影响

- 独立开发不是现在的选项（缺工程经验 + 缺经济安全网）
- 但 3-5 年后是真实可行的路径
- 现在要做的：保持 Game Jam 习惯、积累设计感、培养完整交付能力

## 五、每周 5 小时的方向建议

| 时间 | 做什么 | 目标 |
|------|--------|------|
| 周一 1h | 读一个 UE 模块源码 | 建立"看源码"的习惯和能力 |
| 周三 1h | 用 Profiler 分析一个性能问题 | 培养性能直觉 |
| 周五 1h | 做一道系统设计题（四步法） | 培养表达能力 |
| 周末 2h | 做一个小型技术 demo 或写博客 | 把"知道"变成"能做 + 能说" |

## 六、"10 年后还有价值"的能力

1. **系统架构设计能力** — 引擎会换，架构能力不会过时
2. **性能优化直觉** — 硬件在变，但 Cache 友好/内存布局/并发模式是永恒的
3. **AI 协作能力** — 未来的程序员 = 架构师 + AI 指挥官
4. **完整交付能力** — 能独立把一个想法从原型做到上线
5. **技术表达能力** — 能把复杂系统讲清楚的人永远稀缺
