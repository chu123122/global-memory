# 学习模式教学路径偏好

**规则**：学习模式（/learn）下教 C++/UE 概念时，必须以**当前正在做的项目代码**（如 XDAdaptivePerformance 插件源码）为线，按实际调用顺序展开。通用 C++ / CPU 架构 / 教科书背景知识只在被那段代码用到时**就地补最小集**，不超出代码语境。

**Why**：
- 用户时间紧（入职第一个任务 + 秋招准备），离开项目讲通用基础会"学得抽象"
- 面试讲的是"我做过什么"（项目细节）而非"我懂什么"（CPU 架构八股）
- 2026-04-28 学习 std::atomic 内存序时翻车一次：从 store buffer / x86 vs ARM 重排起讲，用户立刻反馈"我们不是应该先围绕引擎源码学习吗，优先关注和当前插件更加相连的部分"

**How to apply**：
- 每节起点是项目里一段**真代码片段**，不是概念定义
- 不离开代码超过 30 行讲通用知识
- 推荐顺序按"项目代码的执行时序"走（如插件的启动时序图），不是按教科书章节顺序
- 通用底层（CPU 重排 / 编译器优化 / 内存模型）只在用户问"为什么这么写"且代码层解释不了时才下钻
- 反例：从 `int data; bool ready;` 这种最小 demo 起讲——这是教科书路径，不是项目路径
- 正例：从 `MonitorPtr.store(M, release)` 这一行真代码起讲，被问到"release 是什么"时再补内存序

**对照学习地图**：`D:/ClaudeTasks/active/xd-adaptive-performance-refactor/LEARNING-ENGINE-MAP.md` §二启动时序图就是"代码线"的可视化，§五推荐顺序是"通用知识对应"——两条线要融合，不能割裂。

## 升级（2026-04-28 同日二次反馈）：自学清单模式

进一步偏好——**连"逐节带学"都嫌慢，要直接看源码**。

**新模式**：
- AI 提供精准源码清单（文件路径 + 行号区间 + 一句话看点 + 1 个自检题）
- 用户自己看，看不懂回来问"具体某一段"
- AI 切换到**被动模式**：答疑 / 出测试题 / 收知识卡，不主动展开教学
- 触发：用户说"给我点源码推荐我自己看"/"直接给清单"/"我自己看"

**清单格式标准**：
- 表格列：文件 / 行 / 看什么 / 看完自检
- 按"实际调用链顺序"排，不是"教科书章节顺序"
- 给推荐看的顺序（消化时间估算）
- 留 4 种回访接口：贴行号问 / 测自检 / 收 knowledge / 跳节

**与"贴源码线"的关系**：贴源码线是"AI 讲课时贴本插件源码"；自学清单是"AI 把课不讲了，给清单让用户自己读"。两条都符合用户的根本偏好——少听 AI 讲，多读真代码。

**判断点**：用户说"看完一组想测/想总结" → 主动出题/写 knowledge；用户没要求 → 不主动展开。
