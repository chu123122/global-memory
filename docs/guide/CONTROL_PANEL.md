# 主控面板怎么用

这份是给人类看的短说明。你不需要先理解所有 harness 脚本，只要按下面流程用就行。

## 一句话版本

双击：

```powershell
harness\control_panel.bat
```

打开后先看 **总览**。如果总览说有变更，就去 **同步** 页先点 **生成同步预览**，确认没问题再点 **一键同步 / 检查点推送**。

右侧默认显示的是面板替你提炼出来的结论：**现在是什么状态、下一步该点什么、为什么**。命令行原文默认隐藏，只有排查问题时才勾选 **显示原始命令输出（调试用）**。

面板会自动做两件事：

- 每 10 秒静默刷新一次快速状态。
- 每 2 秒读取一次外部事件。AI 或脚本可以调用 `panel_api.py`，消息会显示在 **外部事件** 页和右侧输出区。

## 最常用流程

1. 打开面板。
2. 在 **总览** 点 **刷新快速状态**。
3. 如果只是想确认系统健康，点 **运行完整体检**。
4. 如果看到 Git 有变更，去 **同步** 页点 **生成同步预览**。
5. 预览里的文件分组看起来正常，再点 **一键同步 / 检查点推送**。
6. 如果体检或索引有问题，去 **修复** 页点 **安全修复：索引 / 统计 / 路径**。
7. 如果你想让 AI 给建议，去 **AI 执行** 页点 **运行 AI 诊断 / 计划**。V1 不会让 AI 自动改仓库。

## 每个页签是干什么的

| 页签 | 你什么时候看 | 简单解释 |
|---|---|---|
| 总览 | 一打开就看 | 看 Git 是否有变更、legacy daemon 是否在跑、最近体检是否正常。 |
| 修复 | 索引、统计、路径漂移时 | 做本地安全修复，不提交、不推送。 |
| 同步 | 准备保存当前改动时 | 先预览 checkpoint，再一键提交并推送。 |
| 守护 | 排查 legacy 自动同步兼容进程时 | 查看、启动、停止 legacy auto-sync daemon；semantic refresh 不需要它。 |
| AI | 想让 AI 帮你分析维护问题时 | 只做诊断和计划，不自动执行。 |
| 事件 | 想看 AI/脚本发来的状态时 | 显示 `panel_api.py` 写入的通知。 |
| 历史 | 想看最近发生了什么时 | 看语义提交、checkpoint、维护日志和维护报告。 |

## V1.1 新增的两个可视化区域

| 区域 | 在哪里 | 用来干什么 |
|---|---|---|
| 变更文件明细 | **同步** 页 | 直接看 Git 状态码和文件路径，避免只看分组摘要。 |
| 最近事件列表 | **事件** 页 | 看 AI/脚本发来的历史事件；`warning/error` 会用更醒目的颜色。 |
| 当前结论面板 | 右侧 | 默认只看脚本提炼后的结论、下一步和关键数据。 |

## 调试输出什么时候看

平时不用看命令行。只有这些情况再打开右侧的 **显示原始命令输出（调试用）**：

- 某个按钮显示运行失败。
- 结构化结论看不懂，需要看脚本原始 JSON。
- 你在改面板本身，需要确认命令参数。

## 哪些按钮是安全只读

这些按钮不会改文件、不会提交、不会推送：

| 按钮 | 作用 |
|---|---|
| 刷新快速状态 | 快速看 Git、legacy daemon、最近提交。 |
| 运行完整体检 | 跑健康检查矩阵。 |
| 生成同步预览 | 只看这次 checkpoint 会包含什么。 |
| 查看最近提交 | 区分语义提交和 checkpoint。 |
| 生成维护报告 | 打印当前状态、能力边界、问题和建议。 |
| 查看 auto_sync.log | 看 legacy 自动同步日志尾部。 |
| 运行 AI 诊断 / 计划 | 让 AI 给建议；V1 不自动改文件。 |
| 刷新外部事件 | 读取 AI/脚本通过 `panel_api.py` 发来的通知。 |

## 哪些按钮会有副作用

这些按钮点之前要看清楚确认框：

| 按钮 | 会发生什么 |
|---|---|
| 安全修复：索引 / 统计 / 路径 | 可能修改本地文件，但不会提交和推送。 |
| 一键同步 / 检查点推送 | 会提交并推送当前变更。 |
| 启动守护进程 | 会启动 legacy 后台 Git 自动同步进程；默认不需要。 |
| 停止守护进程 | 会停止 legacy 后台 Git 自动同步进程。 |
| 重新部署 Bootstrap | 会重写 `~/.claude` 下的 junction/settings，属于高风险操作。 |

## 你看到这些状态时怎么办

| 看到什么 | 建议 |
|---|---|
| `dirty=True` | 仓库有未提交变更。去 **同步** 页先生成同步预览。 |
| `behind > 0` | 本地落后远端。真实同步前会先 `pull --rebase`。 |
| `Daemon：running=False` | legacy daemon 未运行；默认可忽略。Git 同步走 **同步** 页预览后手动推送，semantic refresh 由 one-shot worker 处理。 |
| `WARNING` 但没有 `ERROR` | 通常不是阻塞；先看输出区的说明。 |
| `ERROR` | 不要急着同步，先看输出区最后几行，或生成维护报告。 |

## 这面板到底解决什么问题

它不是新的 AI 代理，也不是替代 Claude/Codex 的终端。

它做的是把原来散在脚本里的维护动作收成一个人类入口：

| 原来 | 现在 |
|---|---|
| 不知道该跑哪个脚本 | 先打开主控面板。 |
| 不知道 legacy daemon 有没有 | 看 **守护进程** 页；默认 Git 同步仍以 **同步** 页人工预览为准。 |
| 不知道当前改动会怎么提交 | 先点 **生成同步预览**。 |
| 不知道这套体系健康不健康 | 点 **运行完整体检** 或 **生成维护报告**。 |
| 不想让 AI 直接乱改 | V1 只允许 AI 诊断和计划。 |

## 外部 AI 怎么把消息显示到面板

这不是 HTTP 服务，没有端口，也不用联网。它是一个本地 CLI 事件入口。

AI、脚本或你自己可以运行：

```powershell
python harness\panel_api.py notify --source ai --level info --title "分析完成" --message "建议先生成同步预览。"
```

面板打开时会自动显示这条消息；面板没打开时，消息会先写进：

```text
~/.claude/logs/control_panel_events.jsonl
```

下次打开面板后也能看到最近事件。

## 记住这三个规则就够了

1. **先看总览。**
2. **同步前一定先预览。**
3. **带确认框的按钮都先停一下，看清楚再点。**
