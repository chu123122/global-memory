# 反馈层规格

> 同构骨架：定位 → 职责边界 → 接入 → 接出 → 本层细则 → 引用铁律 → 强制点。
> R 编号权威 = `../RULE_ENFORCEMENT_MATRIX.md`。
> **特殊**：本层几乎不被 AI 读——hook 自动跑。本规格主要给人/维护层看。

## 定位

每轮把可能相关的记忆**主动喂回**给执行层 AI。**纯契约层**：只做确定性召回 + 排序 + 注入，**采纳判断不在本层**（用不用 = 执行层 AI 读到注入后自己判）。

> 反馈层「准不准」= 实现（确定性 score/截断，可调，不是判断）；「用不用」= 执行层判。这化解了"外三层无判断 vs 召回要判断"的伪冲突——召回是检索算法不是判断。

## 职责边界

### 做
- 每轮 UserPromptSubmit 从 prompt 生成 Context Brief（top-N 相关记忆指针）。
- 注入为附加上下文（YAML 简表）。
- 纯只读 + fail-open（异常/超时静默返回，不报错不阻断）。

### 不做
- 不造知识（只指现有记忆）。
- 不判该不该采纳（执行层判）。
- 不写库（写 = 沉淀层）。

## 接入流程（每轮自动）

```
UserPromptSubmit → retrieve_inject.py（hook，自动）
  → 解析 prompt（MIN_QUERY_LEN=3，过短跳过）
  → 按 keywords/tags 匹配记忆 + 当前 task handoff
  → top-N 指针，超时 1.0s 内
```

## 接出流程（注入格式）

```
注入 YAML 简表（schema_version / task / stage / relevant_pointers[path,why,summary] / load_strategy / warnings）
  → 执行层 AI 读到 → 自行判断是否 just-in-time 加载指针指向的文件
  → 命中/未命中记 retrieve_calls.jsonl（供维护层分析）
```

注入的是**指针 + 一句话 summary**，不是全文——执行层按需 just-in-time 读原文。

## 本层细则

- **fail-open**：任何异常/超时 → 静默返回，无 brief 无 error。可 `HARNESS_RETRIEVE_INJECT=0` 关。
  > 与执行层 R9 恢复边界**正交**：本层 fail-open = 召回故障静默不阻断业务；R9 = 构建/测试/部署失败的恢复动作。不同场景，不冲突。健康度（命中率/空召回）由维护层观测。
- **只读**：永不写记忆库；只写自己的调用日志 `logs/retrieve_calls.jsonl`。
- **排序可调不是判断**：score/截断阈值 = 操作细则，下沉 script 旁。

> 阈值（N、TIMEOUT、MIN_QUERY_LEN）/ 匹配算法 = 操作细则，不在本规格。

## 引用的全局铁律（链接 `../agents/CLAUDE.md`）

- R8 AI 只做判断活（召回=确定性变换用代码，正是本层为何无判断）。

## 强制点

本层是**自动注入**非约束拦截，无 PreToolUse 强制点。健康度（命中率/空召回）由维护层观测 `analyze_retrieve_log.py`（S2 只读报表）。
